## 前提

本人が狭い／短い画面の例外とexact packageを承認し、公開候補sourceを固定した後に実施する。同試験App ID・保存版・変更前9プロパティ・全root基準を照合。アプリの元データは隔離架空fixtureのみ。実データ、権限、接続同意、保存・取込フローを試験に使わない。

## 1. コンパイルと読戻し

- 9プロパティ適用後にCheckerを確認。数式エラー0でも実表示合格とは分ける。
- 2画面全量を読戻し、r5から9プロパティだけ、86control構造不変を確認。
- 未承認の再配置、追加control、式の変更があれば停止し、再レビューする。

## 2. 見た目とpointer

- 通常900×600／1366×768／1920×1080：summaryと対象が固定、本文だけを末尾まで移動。
- 450×768／683×768：750px内容へrootの正規縦横スクロールで到達。960×768は通常固定。
- 実Chromeメニュー200%を確認し、実効viewportを採取。CSS幅縮小やStudioデバイスpreviewの倍率で代替しない。
- 9月仮例と11月登録済み0の両方で、名称・根拠・金額の24欄を一つずつ全文確認。内部文字がclipされていないことを確認。
- 対象職員、月選択、summary3値、ホーム、職員検索、支給開閉、控除開閉、再計算が正規pointerで到達すること。原本文言・情報を消したり文字サイズを縮めて合格にしない。
- 短い広幅では縦scrollbarのgutter分の小さな横移動もあり得る。左右端と最終行が通常操作で届くことを確認。
- Studio外側previewスクロールとアプリrootスクロールを別々に記録。公開後Playerで同じ観測を繰り返す。

## 3. MAN-R6-KEYBOARD-001（E2Eポインターケースとは別）

- 既に可視で操作可能な月選択を通常clickで選択し、開いていればEscapeで閉じる。現在のfocusを記録する。DOM focus()で位置を強制しない。
- TabとShift+Tabで月選択・ホーム・職員検索・支給／控除開閉・再計算を巡回し、focus ringと対象文字が読めることを確認する。
- focusに伴う移動は操作可能なroot／本文のみ。hidden祖先が動いて文字切れを隠していないこと、外枠外へfocusが消えないことを確認する。
- 開閉と再計算は内蔵仮例だけで操作し、支給・控除の状態と登録済み0が区別されることを確認。保存等のデータ書込み操作は行わない。
- focus順・移動・clipの証拠が取れなければNOT_RUN/BLOCKEDとする。マウス到達をTab/focus PASSへ転記しない。

## 4. 往復・状態

- 本文末尾かつ右端まで移動した状態で200→100へ戻す。不要になったrootの両offsetが自然に0へ戻り、summaryが元の位置で固定されること。

- 支給／控除を独立して閉じ、空白・不要Tab対象が残らず、再展開後に末尾文字へ到達できること。
