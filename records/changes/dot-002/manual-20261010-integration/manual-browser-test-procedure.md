# DOT-002 / PAY-REQ-HTML-REWORK-001 ブラウザー実動確認手順

この手順は未実施項目を残さず確認するためのものです。手順の存在、リンク先ファイルの存在、JavaScript模擬試験の合格だけで、ブラウザーでの操作合格にしないでください。

## 1. 対象と開始条件

- 対象: 配布ZIPでは `viewer/docs/requirements/standard-template/index.html`。Workのリポジトリ作業ツリーでは `docs/requirements/standard-template/index.html`。
- 対象は静的資料だけです。Power Apps、実データ、GitHubへの書込み、公開、アクセス権変更は行いません。
- 最終版のハッシュ一覧と配布物のハッシュを照合し、使用ブラウザー名・版、OS、URLの方式（file / localhost HTTP / 承認済みURL）、表示幅、JavaScript状態を記録します。
- 展開フォルダーの構造を保ちます。PCでfile方式を使えないときは同じPCのローカルHTTPサーバーを使います。例: 配布物のルートで `python3 -m http.server 8765 --bind 127.0.0.1` を起動し、そのPCのブラウザーで `http://127.0.0.1:8765/viewer/docs/requirements/standard-template/index.html` を開きます。Workのリポジトリルートで配信する場合は `http://127.0.0.1:8765/docs/requirements/standard-template/index.html` です。確認後にサーバーを終了します。
- 別ホストのlocalhostをiPhone用URLと案内しません。iPhone用URLを用意する必要がある場合は、配置先・閲覧範囲の承認を別途取得します。勝手に公開やトンネルを作りません。
- DevToolsなどが組織ポリシーで禁止されている場合は回避しません。利用できる環境に作業を戻します。

## 2. 実行記録

各項目は PASS / FAIL / NOT_RUN のいずれかとし、日時、対象URL、操作、期待結果、実結果、スクリーンショット、必要なら不具合再現手順を残します。直した項目は同じ手順で再確認します。

### A. PC表示と業務利用者の読取り

1. 通常ブラウザーを1280pxのCSS表示幅にします。トップレベルで入口を開き、見出し、主要ナビ、4つの読み始め先、確定境界を読めることを確認します。
2. 「業務の流れから読む」→ WF-13「人給出力・照合・差分再出力」を開きます。
3. 誰が開始するか、どの画面を使うか、通常の完了条件、差分訂正の戻り先、外部人給との受渡しを、図と工程表を使って説明できるか確認します。
4. 状態が「記載の充足」「要件の判断」「実装の状態」「実機の検証」に分かれており、確定要件を実装済みと誤解しないことを確認します。
5. 入口、業務一覧、WF-13の図、画面一覧をそれぞれ撮影します。画面外の情報はスクロールして確認し、全ページの横スクロールや文字切れがないか確認します。

### B. 関連資料と元の要件・位置への戻り

1. 「標準の章立て」→ 2.5.1「外部インタフェース一覧」を開きます。
2. ページ下部の根拠資料から payroll-interface-decisions-20261008.md を開きます。HTMLとして本文が表示されることを確認します。ファイル名やリンク文字列だけの確認で終わりにしません。
3. 冒頭の「元の要件（資料ID 2.5.1）へ戻る」を操作し、sections/2.5.1.html の section-2.5.1 に戻ることを確認します。
4. 再び資料を開き、ブラウザーの戻るで、呼出元ページと元のリンク付近のスクロール位置が復元されるか確認します。ページ内の戻りリンクによる見出し復帰と、ブラウザー履歴による位置復元を別項目で記録します。
5. 要件ID I12 → 根拠行へのリンク → 行アンカー → 元のI12へ戻る、の往復を確認します。
6. 画面一覧 → FUT-JLINK → 既存の詳細ワイヤーフレーム → 元のFUT-JLINKへ戻る、を確認します。新しいタブを開く場合はその動作も記録します。
7. WF-13 → 操作定義 → 元のWF-13へ戻る、を確認します。
8. 関連資料を2段階たどる場合にも、戻り先が別の要件へ意図せず変わらないか確認します。

### C. 設計・構築者のID追跡、検索、未設定抽出

1. 要件ID・操作の一覧で I12 を入力し、要件カードと関連する操作が表示され、無関係なカードが絞られることを確認します。
2. I12を開き、根拠資料・根拠行、OP-JLINK-CONFIRM、WF-12 / WF-13へ移動できることを確認します。
3. 検索を全角の「ｉ１２」、本文語「給与簿」、複数語で試します。Enterでも検索できることを確認します。
4. 対象を「操作」に変え、操作だけになることを確認します。
5. 存在しない語 QA_NONEXISTENT_a7d892 を入力し、0件と案内が表示されることを確認します。
6. リセットし、全件表示と検索欄へのフォーカスを確認します。
7. 「要件未設定」を開き、状態「要件未設定」「一部設定」「記載済み」を切り替えます。未設定抽出には未設定を残した一部設定項目が含まれることを確認します。
8. 状態と「給与簿」を組み合わせ、表示件数と内容が一致することを確認します。リセットで検索と状態の両方が解除されることを確認します。
9. 絞込結果から詳細に移動し、ブラウザーで戻ったときの検索語・選択条件・結果・位置を記録します。条件が意図せず失われる場合は再現手順を残します。

### D. SVG拡大・移動・キーボード

1. WF-13の「＋拡大」を操作し、150%、200%、最大400%で実際に図が大きくなることを確認します。数値だけの変化を合格にしません。
2. 図枠を横・縦に移動し、端の工程・戻り経路・ラベルまで読めるか確認します。
3. 「全体に戻す」で100%と原点に戻ること、100%の縮小と400%の拡大が無効になることを確認します。
4. マウスを使わずTabで主要リンク、検索、絞込、リセット、図枠、図中の操作リンクに移動します。フォーカスが見えること、Enterで操作できることを確認します。
5. 図枠にフォーカスし、矢印キーで横・縦へ移動できることを確認します。図外の通常ページ操作と干渉しないか確認します。
6. WF-01、WF-10、WF-12、WF-13、画面遷移図のような長い図・分岐図も同様に確認します。

### E. 390px・375px幅

1. 通常ブラウザーの対応するレスポンシブ機能か、利用可能な狭幅ウィンドウで、390pxと375pxのCSS幅をそれぞれ確認します。
2. QA専用iframeを使う場合は「狭幅CSS viewportでの確認」と明記します。iPhone実機、Safari、タッチ操作の確認に読み替えません。トップレベルの履歴・戻りはBで別に確認します。
3. 入口、業務一覧、WF-13、FUT-JLINK、2.5.1、根拠資料、I12、検索一覧、未設定一覧を実際に開きます。
4. 本文、ボタン、状態表示が重ならず、押せることを確認します。表・図の枠内スクロールと、ページ全体の不必要な横スクロールを区別します。
5. 図を拡大し、横・縦へ動かしてラベルが読めることを確認します。スマートフォンの実機があれば指での操作も別に確認します。
6. 関連資料を読むために全62資料を長い1ページでスクロールする必要がないことを確認します。
7. 幅ごとに入口、検索、図の拡大中、出典本文のスクリーンショットを残します。

### F. JavaScript無効

1. 使用前の設定を記録し、そのブラウザーで許可された通常の設定方法で対象ローカルページのJavaScriptを無効にします。ポリシーで禁止されている場合はNOT_RUNです。
2. 再読込みして、入口 → 章 → 要件 → 根拠資料の本文と普通のリンクが残ることを確認します。
3. 動的な戻りリンクに依存せず、資料の参照元一覧から2.5.1やI12に戻れることを確認します。
4. 検索・図の拡大が使えない旨の案内を確認します。静的な図と工程表、ブラウザーのページ内検索を使って必要な内容を読めることを確認します。
5. 検索ボタンなどを操作しても資料を失わないことを確認します。
6. 設定を元に戻し、再読込みして検索・図の操作を再確認します。

### G. 旧リンク、PCローカルファイル、Safari、Quick Look

1. 従来の index.html#section-2.5.1 を開き、対応する節に進めることを確認します。
2. 従来の review/pay-html-001/workflows/wf-13.html、wireframes/fut-jlink.html から新資料へ移動し、必要な戻り経路を確認します。
3. HTTPで確認した操作を、PCで直接開いたfile方式でも別に確認します。利用環境がfileを禁止している場合はNOT_RUNです。
4. Safari/iPhoneが実際に利用できる場合だけ、機種・OS・Safari版・承認済みURLと結果を記録します。Chromiumの狭幅確認からPASSを転記しません。
5. Quick Lookは通常ブラウザーと別項目にします。単独の閲覧要約が読めるかを確認し、リンク・検索・拡大の互換性を保証しません。
