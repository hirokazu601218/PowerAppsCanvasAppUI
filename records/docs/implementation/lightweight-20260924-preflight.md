## 確認済み
- 要件は画面要件9章・詳細設計10章・LT追加受入を適用。表示開始月～終了月、未登録月非表示、同月正常複数レコード全件表示は確定済み。
- 編集先はSTATUSに記録されたSTUDIO_EDIT。隔離3テーブルを利用。
- 既存の無人公開ブリッジは既存プロパティ変更に限定され、新規部品・構造変更は対象外。今回のギャラリー化を既存ブリッジへ無検証で流さない。
- `docs/testing/automatable-20260919/observed-control-catalog.json`は過去の816部品の台帳。名前による抽出ではPayrollModal関連334、Ledger関連89、Resident関連14、PDF関連3。分類間に重複があるため合算は削除数にならない。最新Studioの削除台帳ではない。
- 正式HTML版1.01のreport.jsは元の`crb3c_commutes`と`crb3c_staffbasics`を取得する。一方、studio_edit_fixtures.pyは隔離テーブル専用のUUIDv5でGUIDを生成する。編集用GUIDを既存HTMLへ渡すだけでは参照先が一致しない。編集用HTMLの明示的な接続設定または別リソースを用意し、元テーブルへのフォールバックを行わず、移送時に参照先を照合する必要がある。

## 接続と停止理由
- Makerの古い表示には所有者名が残っていたが、更新後の実セッションは「Power Apps 自動テスト」と確認。
- 所有者への切替のためにサインアウトを試みたところ、自動承認審査が拒否。理由は、既存セッションを終了する操作の明示承認を今回の指示から確認できないこと。サインアウトは実行されていない。
- work-policyにはアカウント切替の継続承認があるが、自動審査の拒否を迂回しない。ユーザーへ「現在のテスト用アカウントをサインアウトし、所有者アカウントで入り直す」操作の承認を求める。
- GitHub上の過去ソースを、現行編集用アプリの読戻し済み基準として扱わない。

2. 編集用・安定版の版と復元元、現行6画面・App.Formulas・接続先・帳票ボタンを取得する。
3. 過去台帳との差分と依存参照を照合し、削除前台帳と差分マニフェストを確定。
4. 編集用で6タブ・共通詳細・動的給与列・正式HTML入口・SCR-001配置を段階実装。
5. 改訂版自動化の実際の対象を現行実装と照合。過去チャットのExcel差分同期という推測を適用範囲の根拠にしない。
