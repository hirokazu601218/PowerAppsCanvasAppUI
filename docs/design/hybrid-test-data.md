# Dataverse＋共通内蔵テストデータ（v1.16）

2026-09-16のユーザー指示を実装。職員基本はDataverseの架空25名、未確定の通勤・給与簿等は内蔵合成データを使用する。これは暫定の画面試験用であり、正式な給与計算・法定判定や本番運用を意味しない。

## データの所在

|データ|編集する正本|アプリからの参照|
|---|---|---|
|職員基本|既存Dataverse M_職員基本|StaffBasicView|
|勤務条件・通勤・保険・税控除・給与簿|tests/fixtures/staff-history-synthetic.json|App.FormulasのStaffWorkHistory等|
|認定簿の共通合成値|同JSONのLedgerTemplate|StaffLedgerTemplate|
|生成結果のレビュー用|powerapps/test-data/staff-history.fx（生成物）|App.Formulasと同じ内容|

データの変更はJSONを編集し、`python scripts/automation/render_staff_history.py --write`で共通数式を生成する。引数なしは整合検査のみ。各画面・ラベル・ボタンへの同じデータの複製はしない。Canvas内部には実行用の共通数式として内蔵されるが、レビューではJSONと画面ロジックを分けて確認できる。配布は別途マニフェストの前後値照合、Studioコンパイル、公開後の読戻しを行う。

## fixtureの範囲

- 子データは職員番号末尾003/005/011/012/025にのみ用意。職員番号は必ず12桁文字列。氏名で結合しない。
- 勤務条件7件、通勤5件、社会保険5件、税控除5件、給与7件。共通認定簿値60項目。
- 001/002等は履歴なし、005は金額0、003は過去・現在・未来の勤務条件と給与2回分、011/012は同姓同名で異なる通勤・給与を持つ。
- 通勤fixtureは4月～翌3月の12か月、年度、認定ID、月額、IC運賃、経路、定期代を持つ。現在の画面は従来の4月・10月列を継続し、全12か月列の画面化が完了したとは扱わない。
- 給与fixtureと画面は既存の概要15項目。元のq基準給与簿全列の正式定義・全列詳細表示は今後の業務設計対象。
- 社会保険の年齢・金額・区分は表示試験専用で、法定判定の根拠にしない。
- 住民税欄は削除方針を維持。互換の型付き空データのみ残し、住民税のテーブルやテスト値を追加しない。
- 認定簿の職員番号・氏名・所属・経路・金額は選択したStaffIdから作成。別職員へ切り替えても前の値を使い回さない。
- 履歴0件では認定簿の表示・給与出力を無効化。給与詳細は0件を確認できる。

## 将来のDataverse切替

1. 元テーブルの全列と意味を確認し、ER図・列型・キー・関係を確定する。
2. 既存テスト環境に対象テーブルを追加し、合成データを投入する。
3. 共通取得処理（StaffCommuteHistory等）の戻り値を保ってDataverse参照へ変更する。
4. 12桁職員番号による関連、0件・0円・複数履歴・同姓同名・再読込を同じ受入試験で確認する。
5. 対象種類の内蔵データを除去し、GitHubに切替履歴を残す。

現在の表示用型を正式Dataverseスキーマとみなさない。未確定テーブルの資料提出を、今回の内蔵テスト実装の前提条件にはしない。権限追加・追加料金が必要な変更はユーザーへ事前確認する。

停止中の別Workの認定簿レイアウト・ズーム・PDF保存接続は今回変更していない。
