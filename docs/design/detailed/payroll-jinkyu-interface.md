# 人給Excel出力・給与簿CSV取込仕様

更新：2026-10-08。GitHub正本。業務仕様確定・実装未検証。計算式精査は利用者指示で保留。

根拠：利用者回答、現行VBA・Excel、人給キー仕様とコード表。元Excelの個別データは掲載しない。

## 2. 確定済みの入出力仕様

| ID | 項目 | 確定内容 | 根拠・理由 |
|---|---|---|---|
| IF-01 | 人給インポート用出力 | Excel（.xlsx） | 利用者がCSVとの誤認を訂正。VBAもxlsx保存 |
| IF-02 | 列構成 | 237列、A～IC。順序・見出しを既存サンプルに合わせる | VBAの237列とサンプルの見出しが一致 |
| IF-03 | 行構成 | 固定見出し１行目、データ２行目以降 | 利用者が貼付開始２行目を正常と確認 |
| IF-04 | セル表示形式 | 人給仕様に従い文字列とする | 添付仕様の「セルの表示形式は文字列」に基づく。金額等の文字列の詳細な整形は未入力 |
| IF-05 | 更新区分 | 職員が判断。初回A（新規）、不一致の修正はM（更新） | 利用者の業務フロー。自動判定しない |
| IF-06 | 空欄 | 人給へのインポートで自動的に0へ置換 | 利用者による仕様確認済み。空欄を既存値保持の指定として使用しない |
| IF-07 | 更新対象のキー | 添付仕様の☆付き11項目の組合せ | 画像が「データを一意に特定」と説明 |
| IF-08 | 人給の名称等の列 | 網掛け項目は値を入力してもインポートされない | 添付仕様。237列の見出しから削除する意味ではない |
| IF-09 | 給与簿の戻り | 人給出力の給与簿CSVをアプリへ取り込む | 出力xlsxの変更は給与簿CSVには適用しない |
| IF-10 | 給与簿の編集 | アプリ内は読み取り専用 | R4の合意。差分原因に応じ元データまたは人給を訂正 |
| IF-11 | エラー表示 | エラー行はアプリでも分かるようにする | 利用者の追加指定。人給の結果を受け取る具体方式は未入力 |
| IF-12 | 規模 | 通常約800レコードを想定 | 利用者説明。件数上限・処理時間の基準は未入力 |

Excelの「文字列の表示形式」と「実際に文字列型で値を保存すること」は実装時に揃える。先頭ゼロを落とさず、日付は`yyyy/mm/dd`の固定桁数で出力する。CSV出力の文字コード・区切り・BOMは対象外。給与簿CSVの読み取り設定とは混同しない。

現行の空欄／0の設定を踏襲する方針とする。空文字・未設定セル・数値0・文字列0が元Excelに混在していた事実は、各列で全ての入力型を受け付けることや、必須キーが空欄でもよいことを意味しない。新たな型変換ルールや必須エラー条件は未入力のまま残す。

## 5. 対象期間・通常分・差額分

| ID | 確定事項 | 理由 |
|---|---|---|
| PERIOD-01 | 月末締め、翌月支給。本俸の対象は前月期間（D4=B） | 利用者の業務説明 |
| PERIOD-02 | 本俸の対象年月日は、D4の比較では１か月前とする | D4回答。ただし期間内の具体的な日・採用日との境界は別途精査 |
| PERIOD-03 | 今回の支給対象月の欠勤は通常分から差し引く | D5・D6の補足 |
| PERIOD-04 | 今回の対象月より前の支払済み対象月に生じた差額は差額明細で処理する | 支払済み給与を訂正しない既存方針とD5・D6の補足 |
| PERIOD-05 | 本俸差額・実績差額の対象年月日は差額が発生した対象期間の日付（D7・D8） | 一律に前月とすると、過去月差額の対象を表せない |

D5・D6の「差額を差し引く」理由は欠勤分であり、「過去月差額を通常分から分離するため」とは説明しない。現行の計算項目名「差額」と、欠勤による今回対象月の減額・過去月の差額を区別する。確定した業務上の意味を、未検証の符号・丸め・算定式へ置き換えない。

複数過去月追給を人給の追給行へ集約するR10の既存合意と、対象期間を設定するD7・D8との両立は未確認。過去月別に出力行を分ける、代表日を使う、対象日を削除する等の新ルールは採用しない。月別内訳と出力行の対応を保持する既存要件は維持する。

## 6. 業務フローと状態

1. 確認済み元データから計算版を作る。
2. 職員が更新区分を判断し、人給インポート用Excelを出力する。初回はA。
3. 人給へ取り込み、人給の計算処理を実行する。現行Excelのメインには控除額の手修正が必要との記載がある。どの控除をどう修正するかの新アプリ手順は未入力。
4. 人給から給与簿CSVを出力し、アプリへ読み取り専用で取り込む。
5. 計算結果と給与簿の項目・合計・欠落・余分・重複等を照合する。
6. 不一致原因に応じ元データまたは人給を訂正する。アプリ出力で人給の既存明細を修正する場合は職員がMを指定し、再取込・再計算・再照合する。
7. 差分ゼロを確認して給与班が確定し、支払い済みを記録する。支払済み結果は更新しない。

状態は既存合意の「計算済み → 照合中 → 差分ゼロ確認 → 給与班確定 → 支払い済み」を維持する。未払いの入力・結果が変われば必要な再確認・再計算・再照合を行う。アプリが支払処理自体を実行する要件は追加しない。

保存は計算版・取込回・照合結果を処理回ごとに残す。差分ゼロで支払い確定後は中間版・中間根拠を削除可能とする既存方針を維持し、最終結果・最終根拠・給与簿・支払実績・照合履歴は残す。Excel／CSVファイル自体の継続保存は必須にしない。保存期間・削除権限等の詳細は未入力。

給与簿CSVは既存合意に従い、１～５行目を固定領域、６行目以降を明細領域とし、行数が変動する`【合計情報】`を境界として扱う。合計情報のチェック・保存は不要。未知職員は行を保持して表示し確定を止める、取込失敗時は前回成功分を維持する、数値比較では空欄を0と扱い元の空欄を保持する、という合意を維持する。人給インポート側の空欄0化と、給与簿原値の保存は別の処理である。
