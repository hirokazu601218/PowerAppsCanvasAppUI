# 履歴データ接続前の項目照合（2026-09-16）

対象：職員マスタ検索のDataverseテスト環境。状態：調査結果・設計前提。テーブル作成済みではない。

## 結論

M_職員基本は定義確定・実装済み。履歴は、現在の画面用データ型だけから正式テーブルを作ると元資料の項目を欠落させる。以下の不足を解消してからテーブル定義、架空fixture、接続、回帰試験の順に進める。

現行画面の履歴は型付き空一覧であり、データを保持した完成済みの履歴機能ではない。住民税はユーザーの削除指示に従い今回の新規テーブル候補へ含めない。停止中の別Workの認定簿レイアウト変更も実施しない。

## 実装時の共通案（未作成）

- 職員基本と履歴は1対多。氏名では結合せず、職員番号で取込時に親を照合する。
- 履歴ごとの識別子を持ち、同一職員の過去・現在・将来の行を上書きせず識別する。
- 日付、金額、分数と画面用文字列を分離し、0と空欄を区別する。
- テスト原本はGitHubの架空fixtureとしてアプリソースから分離し、実行時はDataverseを参照する。
- 職員切替・検索0件で別職員の履歴や帳票が残らないことを試験する。
- 実テーブルの列型・キー・関連・権限は全項目照合後に確定する。未決業務仕様を推測して実データ用スキーマへ固定しない。

## 次に受領したい資料
