## 5. 配置の実装原則

自動レイアウトではFillPortions/LayoutMinWidthを明示し、固定座標と混在させない。手動コンテナ/ギャラリーは各X/Y/Width/Heightを明示。列位置は前列X＋前列Widthから算出し、同じX=0の重複を検出する。
行高は最大セル高さ＋上下余白。ラベルと入力欄の高さ、親高さ、TemplateSizeを合わせる。文字を拡大したら親と行も拡大する。横幅不足は水平スクロールか折返しで解決し、極小幅を許さない。
トークンはデザイン基準に従い集約。ただし今回のデータ初期化不要という条件を維持する。App.Formulasを新依存にするなら単独ファイルと適用手順を必ず添える。

### 10.3 共通タブ・履歴・2列詳細

タブは単一のタブリストまたは反復ギャラリーで生成し、タブごとに完成した詳細パネルを複製しない。基本情報、勤務条件、通勤の選択レコード詳細、社会保険、税固定控除は、項目メタデータを次の表示用レコードへ変換して共通詳細ギャラリーへ渡す。

| 列 | 内容 |
|---|---|
| `Section` | タブ区分 |
| `Order` | 表示順 |
| `Key` | 論理項目キー |
| `Label` | 日本語項目名 |
| `Value` | 型を維持した元値または表示専用値 |
| `DisplayText` | 書式適用後の表示値 |
| `IsBlankValue` | 空欄判定。0と区別 |
| `SourceRecordId` | 選択履歴レコード識別子 |

初版の列数は常に2。長文項目も同じ対象とし、ラベル・値の折返しと行の自動高または計算高で全文へ到達できるようにする。固定高さによる切捨て、省略だけで全文確認不能にすること、列ごとに別ギャラリーを作ることを禁止する。実機試験で不適合となった項目だけ、メタデータの`Span=2`等により全幅化できる設計余地を残す。

履歴区分は小さい履歴一覧と選択詳細を分離する。履歴一覧はレコード選択、期間、状態、識別子に必要な列へ絞り、全業務項目は共通詳細ギャラリーへ表示する。

### 10.4 通勤HTML

- 通勤タブは論理上の`T_通勤`のレコードを選択職員で委任可能に抽出し、認定GUID単位で表示する。現行の単一アプリの接続先は隔離`T_通勤_STUDIO`であり、元テーブルへの切替を指示するものではない。
- 「認定簿表示」は、現在職員、選択レコードの親職員、保持職員、選択GUIDが一致するときだけ有効にする。
- 起動先は認定簿HTML Webリソース版1.01以降。現行アプリでは隔離版HTMLを用い、別タブへ選択GUIDだけを渡し、HTML側でDataverseを再読取りする。元データの正式版へ接続先を切り替えない。
- 軽量化実装で`conLedgerModal111`、`pdfLedger111`、関連PDFタイマー・状態・旧入口・PoC入口を削除する。正式HTMLボタンは残す。削除対象は実装前の部品台帳で確定し、HTML起動・0件・職員切替回帰後に読戻す。

### 10.4.1 固定ヘッダーと本文

- ヘッダーには画面名、画面ID、データ取得日時を置き、操作ボタンを置かない。直下の操作領域からサマリー・基本情報・タブ詳細まで、右側を同じ縦スクロール領域に収める。左検索一覧の内部スクロールと給与表の横スクロールは独立させる。
- 操作領域に「保存」などの存続する操作を置き、「変更を破棄」ボタンは置かない。ホーム・支給対象月・文字サイズ・支給明細遷移・詳細表示等も同領域へ集約する。未保存変更を失う画面・職員遷移や読み取りモードへの切替時は、画面要件9.7に従って破棄を確認する。狭幅では折返し、操作の重なりと画面外への脱落を防ぐ。
- 検索条件を縦一列にする。検索入力の虫眼鏡は入力・キーボード操作を妨げない。検索結果は氏名／番号、状態／部署略称の上下関係とし、在籍・退職・採用前の色と文字を併用する。
- 詳細背景とギャラリー見出しの配色は参照画像に合わせる。「履歴一覧へ戻る」と編集対象フッター、「最新データを読込」「検索結果をTSVで出力」は新しい画面に置かない。
- 通勤タブ右上に「認定簿表示」を設ける。有効条件と別タブHTMLへのGUID連携は10.4に従う。

### 10.5 基準給与簿163項目×動的支給月

- 行メタデータは163項目の`Order`、`Key`、`Label`を一度だけ保持する。
- 表示開始月・表示終了月は年月として保持する。開始月が終了月を超える選択は適用せず、入力エラーを示す。開始・終了は年度や12か月に固定しない。範囲変更時は選択職員の必要な給与レコードを再取得し、列コレクションを再生成する。
- `colPayrollColumns111`は取得済みレコードの`crb3c_payment_date`（支給年月日、和暦文字列）を年月へ正規化し、選択範囲内のレコードだけから生成する。未登録月の空列は作らない。同月に複数ある行はすべて別列にし、月見出しに支給年月日と`crb3c_sequence`（番号）等を併記する。同値の場合も行GUIDで一意に対応付け、支給年月日→番号→行GUIDの順で安定して並べる。月単位の合算、上書き、無条件Firstは行わない。
- 外側を163項目の縦ギャラリー、内側を`colPayrollColumns111`の横ギャラリーとする等、表示レコード数に依存して静的コントロール定義が増えない構造を使う。セルは列の行GUIDと項目Keyで取得済みレコードの値へ対応付ける。
- 初版は採用前・退職後だけを理由に月列を除外しない。登録済みレコード内の0、負数、空欄は区別し、範囲内0件は空状態で示す。支給年月日が任意入力のため、空欄・解釈不能の行は黙って除外せず例外件数と対象を表示する。日付書式および同月複数レコードの登録可否条件は登録処理側で精査し、画面側で一意制約を追加しない。
- SCR-005 `scrPayroll`は月次支給明細・試算画面として維持し、基準給与簿163項目画面と統合しない。

### 10.6 データ取得

- 職員選択確定時に、選択職員キーで必要な履歴を区分単位に一度取得し、表示用コレクションへ変換する。
- ギャラリーの各行・各セルからDataverseへ`LookUp`／`Filter`を繰り返さない。支給月×163項目も取得済みレコードとメタデータから表示する。
- 画面初回表示と他画面からの再入場、ブラウザーのF5による再起動では検索結果を取得し直し、選択職員が引き継がれ有効なら詳細も取得し直す。職員切替時は当該職員の詳細・履歴・通勤・給与を取得する。保存成功後は保存対象を再取得する。表示開始月・終了月の変更時は新しい範囲に必要な給与レコードを取得し直す。タブ切替だけでは再取得せず、画面を開いたままの定期更新は行わない。F5の操作案内を画面に記載しない。
- ヘッダーのデータ取得日時は表示対象の取得成功後に利用者の表示タイムゾーンで更新する。複数データ群の取得中は更新完了と表示せず、失敗時は時刻のみ進めない。職員切替時は旧職員の時刻を現職員の取得時刻と誤認させない。
- 所属部署制限、権限エラー、通信失敗、0件を区別し、失敗時に別職員のキャッシュへ戻さない。

### 10.7 削除、部品数、完了条件

削除候補は旧Canvas認定簿・PDF・PoC、給与163項目固定モーダル、非表示住民税、タブごとの重複詳細、未参照コントロール。Git履歴を削除せず、正式画面ソースから除去する。

改修前の当時の基準は全6画面816、旧`Screen1`657コントロール。改修後は画面別・型別に再集計し、`scrStaffMasterSearch`の150～210を当時の設計目標として比較する。さらにApp checker、Studio読込み・選択・保存、公開Player起動、検索、職員切替、タブ切替、HTML起動、給与初期表示・横移動を測定する。文書、ローカルYAML、Studio保存、公開、実機受入をそれぞれ区別して記録する。

**現行の測定条件（`SCR002-PERF-001`）：** 上の816／657は過去版の参考値であり、現在の単一App IDの改修直前値ではない。比較前に当該App IDの保存／公開版と画面別・型別コントロール数を読戻し、同じ環境・fixture・操作・計時方法で改修直後の値と対応させる。計測不能な値は空欄のまま理由を記し、150～210の設計目標だけを合否閾値としない。App checker警告の有無と件数、起動・検索・職員切替・タブ・履歴・HTML・給与初期表示／横移動の時間を別項目で残す。

### 10.8 検索、サイドバー、一覧・タブの状態（`SCR002-LT-002`・`007`、`SCR002-UI-004`・`008`～`010`）

以下は画面要件から導く**実装契約**であり、現在のソース上の式・変数名を読戻した結果ではない。検索入力・所属・状態を確定してから検索を実行し、入力中の表示値、検索確定値、結果件数、選択職員を別状態として管理する。`btnSearch111`を押しても初期7件のままだった[実測FAIL](../testing/current-app-search-observation.md)は、検索成功の設計根拠にしない。0件の正常な検索では職員選択・詳細・履歴・認定GUID・給与を空にし、失敗・権限拒否は0件の成功と区別してエラーを示す。12桁職員番号を数値変換せず、同姓同名の氏名を選択キーにしない。

- サイドバーは展開時の検索入力と結果、折りたたみ時の常設開閉操作を同一親領域内で切り替える。開閉だけでは検索入力・結果・選択職員・ページ位置を初期化せず、職員選択でも自動折りたたみしない。閉じた内部をTab移動の対象にせず、右詳細を空き幅へ拡張する。旧4章の式を現行版で再利用するなら、最新スクリーンのコントロール型・名前・依存式を読戻してから個別に適用する。
- 選択一覧行の背景を、氏名・番号・在籍区分・部署略称を含む連続した青い領域とする。番号セルだけの別背景・二段間の白帯を残さず、左マーカーと選択状態の文字も維持する。行選択は現在表示中の12桁番号と所属条件を再確認して詳細を切り替える。
- 6タブの選択状態は形・枠・背景・文字を併用し、Tab／Enterなどの操作対象と読み取り可能な選択状態を持たせる。タブ切替自体はデータを再読込せず、履歴で選んだ行のキーは区分別に保持する。冒頭の不要テキストボックスは対象を実ソースで特定してから撤去し、履歴選択の入力部品は誤って消さない。

### 10.10 給与簿の月操作と一体スクロール（`SCR002-PAY-005`～`008`）

表示開始月・終了月の**それぞれ**に隣接するカレンダー操作を置き、入力確定時に年月の妥当性と開始≦終了を判定する。不正値なら直前の有効範囲と列を保ち、エラーを表示する。適用時は取得対象職員番号と年月範囲を固定して必要な給与行を再取得し、`colPayrollColumns111`の行GUID順に列とセルを生成する。空・解釈不能な支給年月日には例外件数と行を確認する導線を用意する。0・負数・NULLは表示値で混同しない。

項目名163件を**画面本文と同じ縦スクロール**に置き、項目名だけが独立して動く内側の縦ギャラリーにしない。給与月列の横移動は維持し、固定／追従する月見出しと全セルが同一の列GUIDを指すようにする。「項目（163項目）」行と隣接欄、末尾の「セルを選択すると、ここに全文を表示します。」欄は削除対象とする。長文と識別子はセル折返し、Tooltip等で全文到達可能にする。コントロール名は最新Studio読戻しで特定してから削除し、固定表の旧名称から推定して一括削除しない。

## 12. SCR-001と全6画面の共通設計

### 12.1 SCR-001の上部操作（`SCR001-UI-001`・`002`）

ホームへのサインインは外部認証を前提とする。画面内の確認用所属ドロップダウンと権限切替は**表示確認用UI**として上部操作にまとめ、スマホのPlayerでも開閉・選択・確定できるコントロールを選ぶ。実際の所属／管理者権限の判定は、信頼できるログイン属性とDataverse側の権限に依存させる。両者の値が異なる場合も確認用の選択だけでは他部署のレコードを読取り・更新しない。現行の属性取得元・ロール対応は未確定で、ボタン非活性のみをアクセス制御の完了としない。

### 12.2 業務領域の共通比率（`COMMON-LAYOUT-001`）

親描画領域に対するX=`Parent.Width*4/64`、Width=`Parent.Width*56/64`、Y=`Parent.Height*2/30`、Height=`Parent.Height*26/30`をSCR-001～006へ同じ定義で供給する。各画面に数値を個別直書きしない。900・1100・1366・1600・1920の幅とブラウザー200％・大きな文字では実際の可視領域を観察し、2列詳細が読めない場合は内容折返しまたは横移動で到達可能にする。要件が許していない一律1列化を既定の完成仕様に追加しない。位置式の静的検査だけで可読性の合格とはしない。

各画面の内部機能・CRUDが未定義のSCR-003／004／006は比率とホーム往復の要件だけを本節の設計範囲とし、現行の画面内操作は読戻し・業務判断後に別途定義する。
