## 5. 配置の実装原則

自動レイアウトではFillPortions/LayoutMinWidthを明示し、固定座標と混在させない。手動コンテナ/ギャラリーは各X/Y/Width/Heightを明示。列位置は前列X＋前列Widthから算出し、同じX=0の重複を検出する。
行高は最大セル高さ＋上下余白。ラベルと入力欄の高さ、親高さ、TemplateSizeを合わせる。文字を拡大したら親と行も拡大する。横幅不足は水平スクロールか折返しで解決し、極小幅を許さない。
トークンはデザイン基準に従い集約。ただし今回のデータ初期化不要という条件を維持する。App.Formulasを新依存にするなら単独ファイルと適用手順を必ず添える。

## 6. 帳票・出力

PDFViewerはScreen直下、Documentに生成PDF。モーダルの位置と表示条件は共有する。PDF対象に背面、ボタン、影を含めない。
現行はPDF実験機能が必要。SaveCommuteLedgerPdfは任意接続フローで、ファイル入力とfileurl応答を使う。接続しなければ保存完了を表示しない。既存fxはApp.FormulasではなくOnTimerEnd用。
2ページ改ページ、文字の欠け、拡大、保存ファイル名と対象職員、権限は実機で確認。現在A3横起点だが正式用紙サイズは未決。帳票背景は空様式PNGを内蔵しているため、外部画像URL接続は不要。
TSVコピーは現行の暫定出力。XLSX実装は別のフロー等を設計して承認し、数値型・先頭0・全項目・出力対象を検証する。

テストは`AUT-LAYOUT-001`と`AUT-LIST-001`で公開アプリの座標・色・全9項目・操作を測る。旧版v1.13にも旧仕様の期待値で同じ参照先を検証し、復元テストの誤判定を防ぐ。

## 10. SCR-002軽量化設計（2026-09-24）

本章は1～9章の旧v1.11／v1.14配置と競合する場合に優先する。今回は設計契約であり、現行YAMLや公開アプリが変更済みであることを示さない。

### 10.1 スクリーンと状態

- 現行`Screen1`の改名先は`scrStaffMasterSearch`。部品名末尾`111`は維持する。
- 改名前に`App.StartScreen`、`Navigate`、`Back`、`App.ActiveScreen`、クロススクリーン参照、E2E locator、差分マニフェスト、ファイル名を検索し、改名後に旧名参照0件を確認する。
- 選択タブは`varStaffDetailTab111`で保持し、許可値を`Basic`、`Work`、`Commute`、`Social`、`Tax`、`Payroll`に限定する。
- 職員変更時は選択履歴、選択通勤GUID、給与表示対象を破棄して新職員の対象へ更新する。検索0件では全て空にする。

### 10.2 ルート配置

| 対象 | 式 |
|---|---|
| 業務画面X | `Parent.Width*4/64` |
| 業務画面Width | `Parent.Width*56/64` |
| 業務画面Y | `Parent.Height*2/30` |
| 業務画面Height | `Parent.Height*26/30` |
| 左検索幅 | 展開時360、折りたたみ時48を開始値とし、業務画面幅を上限に制約 |
| 右詳細 | 左検索の右端＋列間から業務画面右端まで |

比率はPower Apps親描画領域内の配置であり、ブラウザーやOSウィンドウを制御しない。1366×768では左右約85px・上下約51px、1920×1080では左右120px・上下72pxを期待値の起点とし、実描画寸法と丸め値を証跡に残す。

### 10.3 共通タブ・履歴・2列詳細

タブは単一のタブリストまたは反復ギャラリーで生成し、タブごとに完成した詳細パネルを複製しない。基本情報、勤務条件、通勤の選択レコード詳細、社会保険、税固定控除は、項目メタデータを次の表示用レコードへ変換して共通詳細ギャラリーへ渡す。

| 列 | 内容 |
|---|---|
| `Section` | タブ区分 |
| `Order` | 表示順 |
| `Key` | 論理項目キー |
| `Label` | 日本語項目名 |
| `Value` | 型を維持した元値または表示専用値 |
| `DisplayText` | 書式適用後の表示値 |
| `IsBlankValue` | 空欄判定。0と区別 |
| `SourceRecordId` | 選択履歴レコード識別子 |

初版の列数は常に2。長文項目も同じ対象とし、ラベル・値の折返しと行の自動高または計算高で全文へ到達できるようにする。固定高さによる切捨て、省略だけで全文確認不能にすること、列ごとに別ギャラリーを作ることを禁止する。実機試験で不適合となった項目だけ、メタデータの`Span=2`等により全幅化できる設計余地を残す。

履歴区分は小さい履歴一覧と選択詳細を分離する。履歴一覧はレコード選択、期間、状態、識別子に必要な列へ絞り、全業務項目は共通詳細ギャラリーへ表示する。

### 10.4 通勤HTML

- 通勤タブはDataverse `T_通勤`を選択職員で委任可能に抽出し、認定GUID単位で表示する。
- 「認定簿を表示」は、現在職員、選択レコードの親職員、保持職員、選択GUIDが一致するときだけ有効にする。
- 起動先は正式HTML Webリソース版1.01以降。別タブへ選択GUIDだけを渡し、HTML側でDataverseを再読取りする。
- 軽量化実装で`conLedgerModal111`、`pdfLedger111`、関連PDFタイマー・状態・旧入口・PoC入口を削除する。正式HTMLボタンは残す。削除対象は実装前の部品台帳で確定し、HTML起動・0件・職員切替回帰後に読戻す。

### 10.5 基準給与簿163項目×動的支給月

- 行メタデータは163項目の`Order`、`Key`、`Label`を一度だけ保持する。
- `colPayrollMonths111`は表示年度と取得済み給与レコードから生成し、年月キー、表示名、順序を持つ。同じ月の重複を検出し、無条件に先頭1件を採用しない。
- 外側を163項目の縦ギャラリー、内側を`colPayrollMonths111`の横ギャラリーとする等、月数に依存してコントロール定義が増えない構造を使う。
- 初版は採用前・退職後による月列非表示を行わない。未登録月を表示するかはデータ契約確定時に決め、0、負数、空欄、未登録の表示を分ける。
- SCR-005 `scrPayroll`は月次支給明細・試算画面として維持し、基準給与簿163項目画面と統合しない。

### 10.6 データ取得

- 職員選択確定時に、選択職員キーで必要な履歴を区分単位に一度取得し、表示用コレクションへ変換する。
- ギャラリーの各行・各セルからDataverseへ`LookUp`／`Filter`を繰り返さない。支給月×163項目も取得済みレコードとメタデータから表示する。
- タブ切替だけでは同じ職員データを再取得しない。再読込、職員変更、対象年度変更を明示的な更新契機とする。
- 所属部署制限、権限エラー、通信失敗、0件を区別し、失敗時に別職員のキャッシュへ戻さない。

### 10.7 削除、部品数、完了条件

削除候補は旧Canvas認定簿・PDF・PoC、給与163項目固定モーダル、非表示住民税、タブごとの重複詳細、未参照コントロール。Git履歴を削除せず、正式画面ソースから除去する。

改修前基準は全6画面816、現行`Screen1`657コントロール。改修後は画面別・型別に再集計し、`scrStaffMasterSearch`は150～210を設計目標とする。さらにApp checker、Studio読込み・選択・保存、公開Player起動、検索、職員切替、タブ切替、HTML起動、給与初期表示・横移動を測定する。文書、ローカルYAML、Studio保存、公開、実機受入をそれぞれ区別して記録する。
