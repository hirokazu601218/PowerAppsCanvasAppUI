# Work / Codex 引継ぎ運用 v1.01

Workが要件・設計を整理、Codexが実装・テスト、Workがレビュー。GitHubのmain上のREADMEから正本へ辿る。チャットだけの決定は次の着手前に文書化する。

| 段階 | 担当 | 出力 |
|---|---|---|
| 変更要求 | Work | 要件ID、目的、変更範囲、受入条件 |
| 設計 | Work | 基本/詳細設計、未決、影響する画面/項目 |
| 開発 | Codex | ブランチ、両YAML、必要Fx、変更履歴 |
| 試験 | Codex | コマンド、結果、画面サイズ、画像、未実施理由 |
| レビュー | Work | 要件IDごとの充足、指摘、残件、受入案 |
| 反映 | ユーザー指示後 | マージ、STATUSとREADME更新、旧版整理 |

## Codexへ渡す文面

PowerAppsCanvasAppUIのREADMEとAGENTS.md、docs/handoff/STATUS.mdから読み始めてください。現行v1.08を基にB案をv1.09へ実装してください。全項目と帳票様式を保持し、docs/testing/acceptance.mdで検証してください。未実施を合格にせず、差分・証跡をPRにまとめ、Workのレビュー前にはマージしないでください。

## PRに必要な記載

- 何の問題を解消したか、要件ID。
- 変更したファイルと設計との差。
- 旧版からの項目数/表示経路の照合。
- 試験コマンドと結果、実機環境、画面サイズ、証跡。
- 未実施・制約・ユーザーが行う操作。
- ロールバック対象コミットと次の作業。

文書はファイル名固定・本文で版管理。画面ソースは0.01刻み。古い版を同じsrcに溜めず、Git履歴から復元する。試験のために必要な画像は証跡として格納し、一時出力やZIPは追加しない。
