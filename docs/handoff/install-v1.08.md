# 職員マスタ検索 v1.08：テストデータ・導入手順・検査結果

> 対象アプリ：共通（自動テスト／ハンドメイド）

職員マスタ検索ダッシュボードと通勤手当認定簿のテスト版です。職員25名と各履歴のデータをYAML内の `Table(...)` に直接埋め込みました。Dataverse、Excel、App.Formulas、App.OnStart、Screen.OnVisibleによるデータ読込は不要です。

## 1. 導入

1. Power Apps Studioで**新しい空の画面**を作成します。任意で `scrStaffMasterSearch_v108` に名前を変更します。
2. [scrStaffMasterSearch_v1.08.paste.yaml](../../src/staff-master/scrStaffMasterSearch_v1.08.paste.yaml) をメモ帳等で開き、内容をすべてコピーします。
3. ツリービューで**画面そのもの**を選んで貼り付けます。コンテナやfx数式バー、読み取り専用のコード表示欄へは貼り付けません。旧版と同じ画面へ重ねて貼り付けないでください。
4. 初期状態で「職員一覧 25件」と「山田 太郎」の詳細を表示する構成です。初期化ボタンやタイマーの実行を待つ必要はありません。
5. **F5／プレビュー**で検索・職員選択・認定簿出力を操作します。編集画面での通常クリックはコントロール選択になるため、ボタン動作の確認はプレビューで行います。

画面直下に `conStaffMaster108` と `pdfLedger108` が並びます。PDF Viewerをコンテナの中に移動すると、以前のPA2131が再発します。

管理用の [scrStaffMasterSearch_v1.08.pa.yaml](../../src/staff-master/scrStaffMasterSearch_v1.08.pa.yaml) は `Screens:` を含む画面定義です。通常の貼り付けでは `.paste.yaml` だけを使います。2種類を両方貼り付ける必要はありません。

## 2. なぜ前版では空欄になったか

v1.07の `btnLoad107.OnSelect` に、次のような処理の区切り漏れがありました。

```powerfx
Notify("テストデータ25名を読み込みました", NotificationType.Success)
Set(varLedgerOpen107, false);
```

この2つの処理の間には `;` が必要です。前回の括弧やプロパティ名中心の検査では、これを検出できていませんでした。今回のローカル構文検査では、この旧式をエラーとして検出しています。

また、貼り付け用YAMLの初期表示は起動タイマーからのデータ読込に依存していました。Studioではタイマーが動くのはプレビューモードです。[Microsoft：Timerコントロール](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/controls/control-timer)

v1.08ではデータ読込用タイマーを削除しました。表示式が直接テスト用のテーブルを返し、操作前は先頭職員を選択扱いにします。検索後に0件となった場合は、先頭職員を再表示せず「該当なし」の状態にします。`Table()` をギャラリーの表示データに使用する方法は[Microsoftの説明](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-table)に基づきます。

| 給与・勤務条件履歴 | 27件 | 現行・過年度・次年度の3件 |
| 通勤支給予定 | 24件 | 1件 |
| 社会保険履歴 | 25件 | 1件 |

認定簿の経路・金額は共通サンプルです。月額3,990円＋6,490円＝10,480円。3・4経路目と2枚目の記入欄は、引き続き未入力の様式です。ダッシュボードの通勤支給予定と認定簿の経路金額は別のサンプルであり、給与計算の整合性を確認するデータではありません。

## 5. PDF生成と保存

PDF機能は前版と同じです。アプリ設定の「今後の機能／Upcoming features」→「実験的／Experimental」→ **PDF function** をオンにして使用します。認定簿を開き、［PDFを作成］を押すと、メモリ内でPDFを生成してPDF Viewerに表示します。PDF機能は実験的機能です。[Microsoft：PDF functionの使用](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/how-to/pdf-function)

ファイル保存まで行う場合だけ、以下のフロー接続を追加します。テストデータの表示や検索には不要です。

| 順番 | Power Automateの構成 | 設定 |
|---|---|---|
| 1 | Power Apps (V2) | 最初の「ファイル」入力を1つ追加。内部キー `file` |
| 2 | SharePoint：ファイルの作成 | 保存先サイト・フォルダー、トリガーのファイル名・内容を指定 |
| 3 | SharePoint：ファイルのプロパティの取得 | 作成したファイルの `ItemId` と同じライブラリを指定 |
| 4 | Power App またはフローに応答する | テキスト出力 `fileurl` に「項目へのリンク」を返す |

フロー名を `SaveCommuteLedgerPdf` とし、アプリのPower Automateペインから追加します。その後、[CommuteLedger_v1.08_SavePDF_OnTimerEnd.fx](../../src/staff-master/CommuteLedger_v1.08_SavePDF_OnTimerEnd.fx) の内容を **`tmrLedgerPdf108.OnTimerEnd`** に設定します。App.Formulasへの貼り付けではありません。

生成・保存後、［保存したPDFを開く］からSharePoint上のPDFを開き、ダウンロードします。保存先への閲覧権限が必要です。YAML単体では、この保存フローは作成・接続されません。

用紙の初期値はA3横です。A4横への変更もできます。帳票の縮尺・2ページへの改ページ・生成結果・保存フローの実行は、利用するStudio／ブラウザーでの確認が残ります。

## 7. 保守と変更履歴

職員・履歴の読み取りは各式の `With({demoStaff:Table(...), ...}, ...)` に埋め込んでいます。初期化漏れを避けるため、同じデータ定義を複数の表示式に含めています。その分YAMLは大きくなります。データ変更時は一箇所だけを書き換えず、関係する式を一括更新してください。実データ接続時はDataverse等の共通データソースへ置き換える設計です。

| 版 | 変更 |
|---|---|
| v1.08 | テスト25名・全履歴を表示式に直接埋め込み。読込タイマーとScreen.OnVisibleへの依存を解消。初期選択・検索0件・初回ページ送りを修正。セミコロン欠落を検出する構文検査とデータ経路の検査を追加 |
| v1.07 | PDF Viewerを画面直下へ移動しPA2131を修正 |

次版以降も0.01刻みで管理します。
