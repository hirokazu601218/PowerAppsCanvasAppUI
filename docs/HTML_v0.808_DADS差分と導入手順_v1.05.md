## 1. 今回どこまで近づけたか

元HTMLの「上部の紺色ヘッダー／左の検索・一覧／右の基本情報・履歴表」という構造、色コード、文字サイズの目安、項目順を移植した。モダン部品の外観へ合わせるのではなく、HTMLの角形・薄い罫線・高密度表を優先する。

完全なピクセル一致、HTMLに含まれるすべての動的列、正式帳票様式の完全移植は達成していない。根拠のない再現率のパーセントは付けない。

| 対象 | この版で実装した範囲 | 残る相違・制限 |
|---|---|---|
| 外観 | 元HTMLの色コード、左400px、ヘッダー54px、右可変幅、表の罫線 | フォント描画・行高・スクロールバーはPower Apps／端末に依存 |
| 検索 | フリーワード、組織、在籍状態のAND条件、検索・条件クリア | 対象は内蔵テストマスタ26項目。実データの全文索引ではない |
| 一覧 | 4列、20名単位のページ切替、行選択、選択色 | HTMLの上下2か所のページャーに対し、この版は上部1か所 |
| 基本情報 | HTMLと同じ9項目・3組×3段のラベル／値表 | 見切れ防止のため1段50pxに固定 |
| 履歴 | HTMLと同順の6区分、職員選択との連動、件数、0件メッセージ、横スクロール | テストデータで定義した固定列。入力データからの動的列検出は未実装 |
| 期間色 | 過去・適用中・未来の色を同じ色値で表示 | テストの再現性のため基準日を2026/09/11に固定 |
| 基準給与簿詳細 | 選択職員の15項目を横スクロールする別枠で表示 | 実際の給与簿Excelにある追加列は未収録 |
| Excel向け出力 | 検索結果26項目のTSVコピー、コピー用テキスト欄 | `.xlsx`ファイル生成・自動ダウンロードではない。先頭ゼロはExcel側で文字列指定が必要 |
| 通勤認定簿 | 職員・所属・認定ID・支給額・架空経路の簡易帳票 | HTML内の認定簿v0.16の69フィールド・複数ページSVG様式は未移植 |
| 印刷／PDF保存 | 表示中の簡易帳票1ページを`Print()`で印刷／ブラウザーのPDF保存 | 複数ページの自動結合、正式PDF生成フロー、モバイル印刷には対応しない |

元HTMLはJavaScriptでExcelファイルを生成し、通勤認定簿では外部のPower Automate手動フローへ誘導する。これを外部接続不要のYAMLだけで同等に実現したとは扱わない。元HTML中の組織内URL・識別情報は移植していない。

## 2. 導入手順

通常の貼り付けには `scrStaffMasterSearch_v1.05.paste.yaml` を使用する。`.pa.yaml` は同じ内容にScreen定義を付けた管理用ソースであり、両方を貼り付ける必要はない。

1. 既存画面を残し、Power Apps Studioで新しい「空白」の画面を作成する。目安は横長1366×768。実際の表示領域は幅1200px以上で確認する。
2. `.paste.yaml` をメモ帳等で開き、先頭から末尾までコピーする。
3. ツリービューで新しい画面を選び、右クリックの「コードの貼り付け」または貼り付け操作を行う。読み取り専用のコード表示欄・fx数式バーには貼り付けない。
4. 右上の再生／F5でプレビューする。テストデータが読み込まれ、先頭職員の詳細が表示される。表示されない場合はヘッダーの「テスト再読込」を押す。
5. 下記の確認例を試す。編集モードで通常クリックしただけでは、ボタンの業務処理は実行されない。

`App.Formulas`、`App.OnStart`、データ接続の追加設定は不要。既存のDadsTokensも変更しない。貼り付け版はTimerで初期化し、画面定義版はOnVisibleにも同じ初期化の入口を持つ。

画面を広いブラウザーに追従させる場合は、アプリ設定の「縦横比を固定」「画面に合わせて拡大縮小」をオフにして検証する。アプリ共通設定なので、既存画面への影響は別途確認する。1200px未満の画面でのスマートフォン対応は今回の対象外とし、無理に文字を縮小しない。

貼り付け操作はMicrosoftの[コード表示・貼り付けの説明](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/code-view)を参照。Studioのバージョン差による検証エラーが出た場合は、エラーメッセージと対象コントロールのコードによる追加確認が必要。

ここでいうDADSは、デジタル庁の仕様全体ではなく、本プロジェクトでPower Apps向けに定めたデザイン基準v1.01を指す。

## 5. 帳票・Excelの使い方と限界

### 検索結果

「検索結果をExcel取得」→「Excel用にコピー」→ExcelのA1へ貼り付ける。コピー対象は現在の20名だけでなく検索結果全件の26項目。Excel側では貼り付け前に職員番号列を「文字列」に設定し、先頭ゼロを保持する。

画面内プレビューは職員番号・氏名・所属・在籍状態の簡易一覧。26項目の帳票レイアウトではない。`.xlsx`自動生成にはPower Automate等を別途接続する必要がある。

`Copy()`は実行ホストの権限に依存する。失敗時はエラー通知を表示し、下部のテキスト欄から手動で全選択・コピーする。[Microsoft：Copy関数](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-copy)

### 通勤認定簿・給与簿

「認定簿出力」または給与簿の「詳細表示」→「Excel用コピー・印刷」から簡易帳票を開く。通勤認定簿は最初の操作だけで帳票を開く。

「印刷／PDF保存」を押すと、PCブラウザーの印刷ダイアログを開く。PDF保存、用紙、向き、背景の印刷はブラウザー側で指定する。印刷時は操作ボタン・コピー欄を非表示にする。12行ごとにページを切り替え、それぞれ個別に印刷する。

`Print()`は現在画面の1ページを印刷する機能で、複数ページの一括出力やモバイル印刷はできない。この版に正式PDFの自動生成・結合・保管機能はない。[Microsoft：Print関数](https://learn.microsoft.com/en-us/power-platform/power-fx/reference/function-print)

検査は、色の変更だけで済ませず、親子構造・セル座標・列幅・行高を検査する方式に変更した。自動レイアウトに直接置くスクロール用の大きな面には、`FillPortions=0`と最小寸法を設定する。表のセルはすべてX・Y・Width・Heightを明記し、ギャラリーのTemplatePaddingは0に統一した。

横スクロールはヘッダーと行を同じ横長の面へ入れるため、左右位置がずれない構造としている。Power Appsの[横コンテナの仕様](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/controls/control-horizontal-container)に基づくが、実機での描画保証ではない。

## 6.1 v1.05で追加した互換性検査

v1.04ではコントロール別のプロパティ照合が不足し、クラシックボタンの `AccessibleLabel` が貼り付けエラーになった。v1.05は次の修正を反映している。

| 対象 | 修正・検査結果 |
|---|---|
| クラシックボタン16個 | 未対応の `AccessibleLabel` を除去。`Text` と `Tooltip`、`TabIndex=0` を設定 |
| コンテナ32個 | ユーザー環境の診断に合わせ `GroupContainer@1.5.0` に統一 |
| 透明な一覧行ボタン | 読み上げ用のTextを設定し、各操作状態の文字色を透明にしてセルとの二重表示を防止 |
| 名前の更新 | コントロール・変数・コレクションを105系へ変更。参照も同時更新 |
| 旧版での検出 | 未対応プロパティ16件・旧版コンテナ32件を検出 |
| 修正版での検出 | 今回のローカル検査ルールでは上記いずれも0件 |
| 全体検査 | 260コントロール・5,334設定を照合。構造・寸法・既存の業務数式の保持を確認 |
| 異常系検査 | 未対応プロパティの再追加、誤記FontColour、旧コンテナ版、YAML重複キーの4ケースを意図的に混入し、検出できることを確認 |

許可リストはMicrosoft Learnの説明と受領したStudio診断を基に作成したもので、Microsoftの完全なバージョン別Source Codeスキーマではない。検査はローカルで実施し、Studioの公式インポーターによる受入、Power Fxのコンパイル・実行、実画面の目視確認は未実施である。機能・レイアウト・テストデータはv1.04から維持しており、検索の期待件数は新たにStudioで実行した結果ではない。

クラシックボタンの読み上げではTextが必要とされ、TooltipをAccessibleLabelと同等とは扱わない。[Microsoft：Button control](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/controls/control-button)
