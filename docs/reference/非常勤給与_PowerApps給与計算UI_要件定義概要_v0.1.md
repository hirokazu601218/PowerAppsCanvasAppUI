## 1. 目的

非常勤職員の給与計算について、職員ごとに異なる単価、勤務時間、適用条件等を取得し、定義された計算ルールに従って計算し、その過程と結果を確認・保存できるPower AppsキャンバスアプリのUIおよび計算方式を試作する。

本段階では、詳細な給与制度・全計算式を確定することではなく、次の方向性がPower Appsで実現可能かを確認する。

- 職員を選択して計算対象を特定する。
- 職員別の変数を複数のテーブルから取得する。
- 変更されるルールとPower Fxによる計算処理を分離する。
- 計算前後の式を画面上で分かりやすく表示する。
- 計算に使用した値、ルールおよび結果を履歴として保存する。

## 2. 対象範囲

### 2.1 本プロトタイプの対象

- 非常勤職員の選択
- 計算対象年月の指定
- 職員別単価の取得
- 対象月の勤務時間等の取得・集計
- 計算ルールの取得
- Power Fx計算モジュールの実行
- 計算前後の計算式表示
- 計算結果および計算根拠の保存
- 日割り計算モジュールの試作

### 2.2 現段階で対象外とする事項

- 既存の人事・給与システムの完全置換
- 全給与項目の本番計算
- 年末調整、再年末調整、退職手当等を含む全業務の実装
- 正式な社会保険料、源泉所得税等の制度判定の確定
- 一括本番処理、支払処理および外部システムへの本番連携

## 3. 基本方針

### 3.1 UI方式

- UIはPower Appsのキャンバスアプリで構築する。
- UI実装用ソースは、Power Appsへ貼り付け可能なYAML＋Power Fxとする。
- HTMLまたは画像によるUIイメージは、ユーザーが明示的に作成を指示した場合に限る。
- UIは画面単位またはルートコンテナ単位で作成・修正し、動作確認できたYAMLを基に反復する。

### 3.2 計算方式

計算方式は、ルールテーブルとPower Fxを組み合わせるハイブリッド方式とする。

| 担当 | 主な内容 |
|---|---|
| ルール・マスタテーブル | 単価、料率、上限額、端数処理、適用期間、計算順序、使用する変数、ルールバージョン |
| Power Fx | 日付判定、条件分岐、計算処理、入力検証、エラー制御、結果保存 |

Power Fxには、テーブルに文字列として保存された任意の計算式をそのまま実行する機能を前提としない。計算ルールテーブルでは計算モジュールコードや使用変数等を指定し、Power Fxが対応する処理を実行する。

## 4. システム構成概要

| 領域 | 役割 |
|---|---|
| キャンバスアプリUI | 職員選択、対象年月指定、計算実行、計算過程・結果確認 |
| 職員・条件データ | 職員基本情報、採用・退職、加入区分等の履歴管理 |
| 変数データ | 単価、勤務時間、住民税等の職員別・期間別データ管理 |
| 計算ルールデータ | 適用する計算モジュール、実行順序、端数処理、適用期間等の管理 |
| Power Fx計算モジュール | 基本給与、日割り、欠勤控除、遡及、社会保険、所得税等の処理 |
| 計算結果データ | 計算結果、使用値、使用ルール、計算日時等の履歴保存 |

## 5. データ構成概要

### 5.1 主要テーブル

| テーブル | 主な役割 |
|---|---|
| M_職員基本 | 計算対象職員の基本情報 |
| T_職員条件履歴 | 採用日、退職日、加入区分等の期間履歴 |
| T_職員単価履歴 | 職員別・給与項目別・適用期間別の単価 |
| T_勤怠実績 | 職員別・日別または月別の勤務時間、欠勤時間等 |
| T_給与調整イベント | 追給、返納、遡及等の調整事由 |
| M_計算ルール | 計算項目、モジュールコード、実行順序、適用期間、ルール版 |
| M_日割りルール | 分子・分母区分、固定分母、端数処理、適用期間等 |
| M_支給控除項目 | 支給・控除項目の定義 |
| M_社会保険料率 | 社会保険・共済等の適用料率 |
| M_源泉徴収税額表 | 課税対象額、扶養人数等に応じた税額 |
| M_住民税 | 職員別・対象月別の住民税額 |
| T_給与計算 | 1職員×1計算回の計算ヘッダー |
| T_給与計算明細 | 支給控除項目別の計算結果および計算根拠 |

### 5.2 変数テーブルの分離方針

すべての変数を1つの汎用テーブルへ格納することを必須としない。データの性質に応じて分離する。

- 単価は、職員単価履歴として適用期間別に管理する。
- 勤務時間は、勤怠実績として勤務日または対象月別に管理する。
- 料率、税額表、住民税等は、それぞれの業務目的に対応するマスタへ格納する。
- Power Fxは、職員番号、対象年月、項目コード、適用期間等をキーに必要な値を取得する。

## 6. 計算ルールとPower Fxの役割分担

### 6.1 テーブルで管理するもの

- ルールID
- 計算項目コード
- 計算モジュールコード
- 使用する入力変数コード
- 出力項目コード
- 計算順序
- 端数処理区分
- 適用開始日・適用終了日
- ルールセット版・ロジック版
- 使用状態
- 画面表示用の自然言語式

### 6.2 Power Fxで実装するもの

- 対象職員・対象年月の確定
- 有効な条件履歴・ルールの抽出
- 各テーブルからの変数取得
- 日付・期間の判定
- 計算モジュールコードによる処理分岐
- 日割り、欠勤控除、遡及等の複雑な計算
- 入力不足、重複、ゼロ除算等のチェック
- 計算結果の表示・保存

## 7. 想定する計算モジュール

| モジュール | 概要 | 初期試作 |
|---|---|---|
| 基本給与計算 | 職員別単価と勤務時間による計算 | 対象 |
| 日割り計算 | 採用日・退職日等を考慮した按分 | 対象 |
| 欠勤控除計算 | 欠勤時間・日数に応じた控除 | 将来対象 |
| 遡及計算 | 新旧単価・既払額との差額計算 | 将来対象 |
| 社会保険計算 | 加入区分、標準報酬、料率等による計算 | 将来対象 |
| 所得税計算 | 課税対象額、扶養人数、税額表等による計算 | 将来対象 |
| 住民税計算 | 職員別・対象月別の登録額取得 | 将来対象 |
| 差引支給額計算 | 支給合計から控除合計を控除 | 将来対象 |

## 8. 基本処理フロー

1. ユーザーが計算対象年月を指定する。
2. 職員マスタから対象職員を選択する。
3. 職員番号と対象年月を基に有効な職員条件を取得する。
4. 職員別単価履歴から対象期間の単価を取得する。
5. 勤怠実績から対象期間の勤務時間等を取得・集計する。
6. 計算ルールから有効なルールと計算順序を取得する。
7. Power Fxがモジュールコードに対応する計算処理を実行する。
8. UIに計算過程と計算結果を表示する。
9. ユーザーが内容を確認する。
10. 計算結果、使用変数、適用ルール、計算日時等を結果テーブルへ保存する。

## 9. UI要件概要

### 9.1 主な入力・操作

- 計算対象年月の選択
- 計算対象職員の検索・選択
- 計算実行
- 計算結果の確認
- 計算結果の確定・保存

### 9.2 計算式の表示

計算実行前は変数名による式を表示し、実行後は実際に使用した値と結果へ切り替える。

| 状態 | 表示例 |
|---|---|
| 計算前 | `[単価]×[時間]=[金額]` |
| Aさん計算後 | `150円×6時間=900円` |
| Bさん計算後 | `200円×4時間=800円` |
| 日割り計算前 | `[月額]×[支給対象日数]÷[月日数]=[日割額]` |
| 日割り計算後 | `300,000円×12日÷31日=116,129円` |

## 10. 日割り計算モジュールの方向性

初期試作では、次の例を用いて日割り計算の実現性を確認する。

- 計算例：月額×支給対象日数÷月の日数
- 計算開始日：対象月初日と採用日の遅い方
- 計算終了日：対象月末日と退職日の早い方
- 支給対象日数：計算開始日から計算終了日までの両端を含む日数
- 端数処理：日割りルールテーブルに設定
- 保存対象：月額、分子日数、分母日数、端数処理前金額、計算結果、ルール版

暦日、所定勤務日、固定分母等の正式な日割り方法は、適用規程を確認して確定する。

## 11. 履歴・監査要件

- 職員条件、単価およびルールは上書きを原則とせず、適用期間別に保持する。
- 計算結果には、使用した条件履歴ID、ルールID、ルールセット版、使用値を保存する。
- `T_給与計算`は1職員×1計算回を基本単位とする。
- `T_給与計算明細`は支給控除項目ごとの縦持ちを基本とする。
- 確定済みまたは支払済みの結果を直接上書きせず、取消・再計算は新しい計算版として追加する。
- 計算結果から当時の計算根拠を追跡・再現できることを目標とする。

## 12. エラー・検証要件概要

- 職員が未選択の場合は計算を実行しない。
- 対象年月が未指定の場合は計算を実行しない。
- 有効な職員条件、単価またはルールが存在しない場合はエラー表示する。
- 同一期間に複数の有効レコードが存在する場合は計算を停止する。
- 必須変数が未登録の場合は計算を停止する。
- 分母がゼロまたは不正な場合は計算を停止する。
- 計算結果保存時には、保存成功・失敗をユーザーへ通知する。

## 13. 初期プロトタイプの確認範囲

初期プロトタイプでは、機能を次の範囲に限定する。

1. 2名程度のサンプル職員を登録する。
2. 職員ごとに異なる単価を登録する。
3. 職員ごとに異なる勤務時間を登録する。
4. `単価×時間`を共通ルールで計算する。
5. 計算前後の式を画面上で切り替える。
6. 使用値と計算結果を計算明細へ保存する。
7. 採用日が月途中の職員について日割り計算を試行する。

## 14. 未決事項

- 本番データソースをDataverse、SharePointリスト等のどれにするか。
- 正式な日割り計算の分子・分母および端数処理。
- 社会保険料をアプリ内計算するか、外部確定額を取り込むか。
- 源泉所得税を税額表参照で計算する場合の正式な税額表構造。
- 複数の単価が月途中で切り替わる場合の期間分割方式。
- 職員単位計算から複数職員一括計算へ拡張する時期。
- 計算ルールの登録・変更・承認権限。
- 計算結果の確認・確定・取消・再計算の業務権限。
