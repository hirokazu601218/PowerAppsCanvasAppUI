現在の要件

総合テストは、複数機能を通す業務シナリオと開始・終了条件を定義してから、一連の業務結果と必要な非機能要件を確認する。公開直後の起動確認や単体・結合の成功を総合テスト完了へ読み替えず、総合テストと業務受入を独立して判定する。

原本の記入ガイド

  • 特に国民等の多数のユーザー（リテラシーも大きく異なる）が利用する場合には、このようにユーザビリティ/アクセシビリティテストを明示的に実施することを推奨します。 ユーザビリティ/アクセシビリティテストは費用が掛かることを理解し、国民や多数の人員が利用するような情報システムで、ユーザー評価によってデザイン・画面遷移等を修正する必要があるものに対してテストを実施することが望ましいです。 主管課側として、意思決定者や基準をある程度決定しておく必要があります。
  • 特に現行システムを更改する場合には、このように互換性評価テストを明示的に実施することを推奨します。
  • セキュリティテストのテスト手法はあくまでも例示となりますので、各情報システムのセキュリティ要件に応じて、テスト手法の追加等をご検討ください。（例）ファジング：潜在的なバグ・脆弱性を検出することを目的として、通常想定されない不正データ等を情報システムに与え意図的に例外処理を発生させるテスト手法。
