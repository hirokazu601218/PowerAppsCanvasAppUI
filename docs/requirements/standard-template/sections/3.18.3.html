アプリの改修は影響分析とケース選定に基づき、変更部品の単体試験および影響先の結合試験を実施する。公開版とGitHub候補ソースの同一性を別に確認し、未実施・未照合を合格にしない。

原本の記入ガイド

  • 他の事業者が保守を行う場合は、本章は以下を参考に記載してください。 記載例：業務アプリケーションに起因する障害については、本システムの運用・保守事業者がプログラムの修正、変更、適用等復旧までの一連の作業を実施するものとする。ただし、受託者の契約期間中における業務アプリケーションの保守においては受託者が実施する。また、契約不適合責任の期間内における障害のうち、障害原因が受託者の責任範囲と判断される場合の一連の作業は、受託者が実施する。
