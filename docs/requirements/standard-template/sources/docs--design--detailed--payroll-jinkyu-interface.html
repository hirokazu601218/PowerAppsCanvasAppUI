人給Excel出力・給与簿CSV取込仕様

更新：2026-10-08。GitHub正本。業務仕様確定・実装未検証。計算式精査は利用者指示で保留。

根拠：利用者回答、現行VBA・Excel、人給キー仕様とコード表。元Excelの個別データは掲載しない。

Excelの「文字列の表示形式」と「実際に文字列型で値を保存すること」は実装時に揃える。先頭ゼロを落とさず、日付はyyyy/mm/ddの固定桁数で出力する。CSV出力の文字コード・区切り・BOMは対象外。給与簿CSVの読み取り設定とは混同しない。

現行の空欄／0の設定を踏襲する方針とする。空文字・未設定セル・数値0・文字列0が元Excelに混在していた事実は、各列で全ての入力型を受け付けることや、必須キーが空欄でもよいことを意味しない。新たな型変換ルールや必須エラー条件は未入力のまま残す。

5. 対象期間・通常分・差額分

ID 確定事項 理由
PERIOD-01 月末締め、翌月支給。本俸の対象は前月期間（D4=B） 利用者の業務説明
PERIOD-02 本俸の対象年月日は、D4の比較では１か月前とする D4回答。ただし期間内の具体的な日・採用日との境界は別途精査
PERIOD-03 今回の支給対象月の欠勤は通常分から差し引く D5・D6の補足
PERIOD-04 今回の対象月より前の支払済み対象月に生じた差額は差額明細で処理する 支払済み給与を訂正しない既存方針とD5・D6の補足
PERIOD-05 本俸差額・実績差額の対象年月日は差額が発生した対象期間の日付（D7・D8） 一律に前月とすると、過去月差額の対象を表せない

D5・D6の「差額を差し引く」理由は欠勤分であり、「過去月差額を通常分から分離するため」とは説明しない。現行の計算項目名「差額」と、欠勤による今回対象月の減額・過去月の差額を区別する。確定した業務上の意味を、未検証の符号・丸め・算定式へ置き換えない。

複数過去月追給を人給の追給行へ集約するR10の既存合意と、対象期間を設定するD7・D8との両立は未確認。過去月別に出力行を分ける、代表日を使う、対象日を削除する等の新ルールは採用しない。月別内訳と出力行の対応を保持する既存要件は維持する。

6. 業務フローと状態

  1. 確認済み元データから計算版を作る。
  2. 職員が更新区分を判断し、人給インポート用Excelを出力する。初回はA。
  3. 人給へ取り込み、人給の計算処理を実行する。現行Excelのメインには控除額の手修正が必要との記載がある。どの控除をどう修正するかの新アプリ手順は未入力。
  4. 人給から給与簿CSVを出力し、アプリへ読み取り専用で取り込む。
  5. 最新版のアプリ計算結果と給与簿の項目・合計・欠落・余分・重複等を照合する。
  6. 不一致原因に応じ元データまたは人給を訂正する。アプリ出力で人給の既存明細を修正する場合は職員がMを指定し、再取込・再計算・再照合する。
  7. 差分ゼロを確認して給与班が確定し、支払い済みを記録する。支払済み結果は更新しない。

状態は既存合意の「計算済み → 照合中 → 差分ゼロ確認 → 給与班確定 → 支払い済み」を維持する。未払いの入力・結果が変われば必要な再確認・再計算・再照合を行う。アプリが支払処理自体を実行する要件は追加しない。

保存は計算版・取込回・照合結果を処理回ごとに残す。差分ゼロで支払い確定後は中間版・中間根拠を削除可能とする既存方針を維持し、最終結果・最終根拠・給与簿・支払実績・照合履歴は残す。Excel／CSVファイル自体の継続保存は必須にしない。保存期間・削除権限等の詳細は未入力。

給与簿CSVは既存合意に従い、１～５行目を固定領域、６行目以降を明細領域とし、行数が変動する【合計情報】を境界として扱う。合計情報のチェック・保存は不要。未知職員は行を保持して表示し確定を止める、取込失敗時は前回成功分を維持する、数値比較では空欄を0と扱い元の空欄を保持する、という合意を維持する。人給インポート側の空欄0化と、給与簿原値の保存は別の処理である。

7. 承認済み画面の処理契約（I1～I12）

画面要件のJLINK-UI-01～11、決定台帳のI1～I12を適用する。画面はホーム→人給連携、同一画面内の支給回の状況／出力／取込・照合。正式画面ID・Canvasコントロール名・Power Fx・フロー名・物理列名は未入力。モック承認は実装・公開の合格を意味しない。

7.1 出力と再出力

支給回選択を共通コンテキストとする。初回は全職員が既定で、職員の絞込みができる。A/Mは職員による一括指定と明細ごとの変更を保持し、出力前に支給回・人数・明細数・A/M件数を確認する。出力データはその時点の最新版の計算結果から作り、出力時の計算版・対象明細・指定A/Mを処理履歴と関連付ける。

再出力では差分に対応する出力明細行だけを初期選択し、職員が変更できる（I9）。差分一覧の一行をそのままExcel一行として出力しない。給与簿行・比較項目・出力明細の対応と多重行集約は未入力であり、人給の11キーを給与簿の照合キーと自動的にみなさない。対応を特定できない場合の操作も詳細化が必要。再出力でA/Mを自動変更しない。

7.2 最新版との照合

給与簿CSVの取込成功分と、選択支給回の最新版のアプリ計算結果を照合する（I5）。利用者が照合対象の計算版を選ぶ操作は設けない。計算版は出力・取込・照合の追跡情報として残し、古い出力版へ戻して一致を作る基準にはしない。

出力後に結果が変わっても最新版を比較し、「出力後に計算結果が変更されています」を表示する（I7）。照合は対象支給回・使用した最新結果の識別情報・給与簿取込回と関連付ける。照合開始後または完了後に計算結果が変われば、その照合の差分ゼロを現行の確定根拠として使わず再照合する。版・更新の識別、同時更新の検出と確定時の再検証の物理方式は未入力。

人給の取込成功／一部失敗／失敗を手入力しない（I10）。給与簿との比較でデータの一致を確認するが、照合結果から人給の取込処理の実行ログや成功状態を創作しない。初期表示は差分のみ、全件へ切替可能。差分列は職員・対象期間・項目・アプリ値・給与簿値・差額（I6・I11）。差額の表示符号・非数値差分の表現は未入力。

7.3 訂正・エラー・確定

差分から原因に応じた勤務条件・勤怠・通勤等の入力画面へ遷移し、戻るとき支給回・職員を保持する。元データ訂正後は再計算し、人給側の修正が必要なら職員指定でExcel再出力→人給→給与簿再取込→再照合を繰り返す。支払済み給与は更新しない。

I8=Cのため、人給エラー行のアプリ表示は要件として残すが、エラーファイル形式・取出し方法・行対応は未入力。人給への直接接続、自動エラー取込、手入力方式のいずれも決定済みにしない。給与簿取込エラーと人給インポートのエラーは区別する。

給与班確定は確認ダイアログなしの確定ボタンで行う（I12）。権限、支給回全体の最新照合、差分ゼロ、未解決行の不存在を確定時に検証する。職員や差分の表示フィルターで判定を限定しない。計算更新で古くなった差分ゼロを使わない。確定と支払い済みの記録は既存の別状態を維持する。
