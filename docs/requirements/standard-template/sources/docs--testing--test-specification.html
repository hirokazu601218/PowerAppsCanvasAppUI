6. 表示・PDFの機械判定ルール

  1. 可視の文字・操作部品だけを測定する。親スクロール内の画面外セルは、スクロール後に測定する。
  2. 文字のバウンディングボックスとセル内側を比較し、はみ出しは1 CSS px以内の丸め差だけ許容。値・文字が実際に欠けていれば丸め差以内でもFAIL。
  3. 隣接する本文・ボタンの重なりは0。罫線、背景、選択マーカー、透明な行ヒット領域は意図した例外を部品ID付きで登録。例外を画面全体へ適用しない。
  4. 表ヘッダーとデータセルの左端・幅は、同じスクロール位置で差1 CSS px以内。親幅の計算には外余白16、必要なスクロールバー安全域を含める。
  5. sidebar幅360/48、右詳細幅差328はアプリ論理px基準。ブラウザ側は実描画倍率を掛けて比較し、スケーリングによる誤検出を避ける。
  6. 画像差分は同じOS・ブラウザ・日本語フォント・DPRで採取。暫定ピクセル許容は比較閾値0.2・差分率0.5%をレビュー起点とし、金額・番号・欠損領域は差分率が小さくても不合格。最終しきい値は初回実画面で校正する。
  7. 可視テキストDOMが取得できない部品は画像／OCRで補完する。OCR信頼不足や矩形抽出不能はPASSにせずREVIEW_REQUIREDとして保留し、結果分類はBLOCKEDまたはH未実施とする。
  8. PDFはパーサーで開けること、ページ数2、MediaBox/向き一致、各ページ画像の枠・文字・対象一致を確認。位置の初期許容は正式空様式比±1mm、業務値・文字欠けは許容しない。
  9. ラスターPDFでテキスト抽出できない場合、OCR＋ページ画像レビューを行う。OCRだけで職員番号・金額の誤字を見逃さない。抽出失敗を空帳票の合格にしない。
  10. フォント12/14/16の数値だけでは読みやすさ合格にしない。Power Apps部品ごとの単位と100%実表示を校正する。

セレクター設計の再発防止ルール

  1. クリックは、表示文字のLabelやその子要素ではなく、実際にポインターイベントとOnSelectを受けるButton等の操作部品を対象にする。Power Appsの透明な行選択ボタンが表示Labelへ重なる場合は、行選択ボタンのroleとアクセシブル名を使用する。
  2. .first()、.last()、.nth()を、複数候補やstrict mode違反を回避する目的で使用しない。使用できるのは、順序自体が仕様であり、候補数と順序を先に検証し、理由をテストコードへ記録した場合だけとする。
  3. 通常の操作・確認には、role、完全一致のアクセシブル名、業務上の一意キー（職員番号等）、対象フレームまたは親領域のスコープを組み合わせ、locatorが1件であることを保証する。
  4. サイドバーやモーダルを閉じた後の状態保持は、閉鎖領域内の非表示セルでは判定しない。選択職員は常時表示される詳細サマリー、検索条件は再展開後の入力値、ページはページ表示部品など、検証目的に対応する安定した表示先で確認する。閉鎖領域については非表示になったことを別に確認する。
  5. クリック後は、対象職員の職員番号・所属など一意な期待結果を確認し、クリックが実際にアプリ状態を変えたことを証明する。表示文字が見えることだけで操作成功としない。
  6. 新しいlocatorは候補版だけでなく、失敗時に復元する直前の成功版でも実行する。版によって意図的に異なる表示は期待値を明示的に分岐し、テストコード自体の誤りで復元失敗を発生させない。
  7. タイムアウト時は、Playwrightのcall log、アクセシビリティsnapshot、スクリーンショットまたはtraceで、クリック遮蔽、非表示、複数一致、アプリ状態不良を区別する。テスト不具合とアプリ不具合を判定してから修正・再実行する。
