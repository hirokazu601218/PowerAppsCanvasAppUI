10.3 共通タブ・履歴・2列詳細

タブは単一のタブリストまたは反復ギャラリーで生成し、タブごとに完成した詳細パネルを複製しない。基本情報、勤務条件、通勤の選択レコード詳細、社会保険、税固定控除は、項目メタデータを次の表示用レコードへ変換して共通詳細ギャラリーへ渡す。

列 内容
Section タブ区分
Order 表示順
Key 論理項目キー
Label 日本語項目名
Value 型を維持した元値または表示専用値
DisplayText 書式適用後の表示値
IsBlankValue 空欄判定。0と区別
SourceRecordId 選択履歴レコード識別子

初版の列数は常に2。長文項目も同じ対象とし、ラベル・値の折返しと行の自動高または計算高で全文へ到達できるようにする。固定高さによる切捨て、省略だけで全文確認不能にすること、列ごとに別ギャラリーを作ることを禁止する。実機試験で不適合となった項目だけ、メタデータのSpan=2等により全幅化できる設計余地を残す。

履歴区分は小さい履歴一覧と選択詳細を分離する。galHistory111.Visibleは4区分かつ該当履歴が複数件のときだけ真とする。選択行は状態、期間の先頭10文字、識別子末尾4文字に短縮し、高さ36px、最大3行を表示する。OnSelectでvarHistoryId111を更新し、全業務項目は共通詳細ギャラリーへ表示する。単一件では選択行を描画しない。

10.4.2 HTML認定簿の帳票・権限契約（SCR002-COM-003）

Canvasから渡す値は選択した認定レコードのGUIDとし、HTML側で隔離通勤レコード・親職員を再取得する。HTMLへの直接アクセスや古いタブのGUIDを再利用した場合も、現在の利用者が親職員の所属を閲覧できるかを確認し、不一致・削除済み・権限拒否なら帳票本文を出さず理由を表示する。画面のボタン活性だけを権限判定に使わない。具体的なログイン属性取得元とDataverseの実効ロールは未決なので、現行の権限実装が成立したとは扱わない。

帳票内の任意列は未登録（NULL／空欄）を0円・0km等の数値0に変換せず、認定ID・親職員・適用期間に対応した選択レコードから表示する。長文がある場合も本文を黙って切らず、正式様式のA4横2ページに収める。印刷CSSでページ区切りと横向きを指定し、ブラウザーの印刷から2ページを1つのPDFとして保存する。実際の印刷設定・ページ数、表示項目の全件一致と他所属拒否は、隔離HTMLと現在の公開版を用いた別の実機・権限試験で判定する。旧A4縦PoCの結果を横向き正式版の合格に流用しない。

10.5 基準給与簿163項目×動的支給月

  • 行メタデータは163項目のOrder、Key、Labelを一度だけ保持する。
  • 表示開始月・表示終了月は年月として保持する。開始月が終了月を超える選択は適用せず、入力エラーを示す。開始・終了は年度や12か月に固定しない。範囲変更時は選択職員の必要な給与レコードを再取得し、列コレクションを再生成する。
  • colPayrollColumns111は取得済みレコードのcrb3c_payment_date（支給年月日、和暦文字列）を年月へ正規化し、選択範囲内のレコードだけから生成する。未登録月の空列は作らない。同月に複数ある行はすべて別列にし、月見出しに支給年月日とcrb3c_sequence（番号）等を併記する。同値の場合も行GUIDで一意に対応付け、支給年月日→番号→行GUIDの順で安定して並べる。月単位の合算、上書き、無条件Firstは行わない。
  • 外側を163項目の縦ギャラリー、内側をcolPayrollColumns111の横ギャラリーとする等、表示レコード数に依存して静的コントロール定義が増えない構造を使う。セルは列の行GUIDと項目Keyで取得済みレコードの値へ対応付ける。
  • 初版は採用前・退職後だけを理由に月列を除外しない。登録済みレコード内の0、負数、空欄は区別し、範囲内0件は空状態で示す。支給年月日が任意入力のため、空欄・解釈不能の行は黙って除外せず例外件数と対象を表示する。日付書式および同月複数レコードの登録可否条件は登録処理側で精査し、画面側で一意制約を追加しない。
  • SCR-005 scrPayrollは月次支給明細・試算画面として維持し、基準給与簿163項目画面と統合しない。

10.6 データ取得

  • 職員選択確定時に、選択職員キーで必要な履歴を区分単位に一度取得し、表示用コレクションへ変換する。
  • ギャラリーの各行・各セルからDataverseへLookUp／Filterを繰り返さない。支給月×163項目も取得済みレコードとメタデータから表示する。
  • 画面初回表示と他画面からの再入場、ブラウザーのF5による再起動では検索結果を取得し直し、選択職員が引き継がれ有効なら詳細も取得し直す。職員切替時は当該職員の詳細・履歴・通勤・給与を取得する。保存成功後は保存対象を再取得する。表示開始月・終了月の変更時は新しい範囲に必要な給与レコードを取得し直す。タブ切替だけでは再取得せず、画面を開いたままの定期更新は行わない。F5の操作案内を画面に記載しない。
  • ヘッダーのデータ取得日時は表示対象の取得成功後に利用者の表示タイムゾーンで更新する。複数データ群の取得中は更新完了と表示せず、失敗時は時刻のみ進めない。職員切替時は旧職員の時刻を現職員の取得時刻と誤認させない。
  • 所属部署制限、権限エラー、通信失敗、0件を区別し、失敗時に別職員のキャッシュへ戻さない。

10.8 検索、サイドバー、一覧・タブの状態（SCR002-LT-002・007、SCR002-UI-004・008～010）

以下は画面要件から導く実装契約であり、現在のソース上の式・変数名を読戻した結果ではない。検索入力・所属・状態を確定してから検索を実行し、入力中の表示値、検索確定値、結果件数、選択職員を別状態として管理する。btnSearch111を押しても初期7件のままだった実測FAILは、検索成功の設計根拠にしない。0件の正常な検索では職員選択・詳細・履歴・認定GUID・給与を空にし、失敗・権限拒否は0件の成功と区別してエラーを示す。12桁職員番号を数値変換せず、同姓同名の氏名を選択キーにしない。

  • サイドバーは展開時の検索入力と結果、折りたたみ時の常設開閉操作を同一親領域内で切り替える。開閉だけでは検索入力・結果・選択職員・ページ位置を初期化せず、職員選択でも自動折りたたみしない。閉じた内部をTab移動の対象にせず、右詳細を空き幅へ拡張する。旧4章の式を現行版で再利用するなら、最新スクリーンのコントロール型・名前・依存式を読戻してから個別に適用する。
  • 選択一覧行の背景を、氏名・番号・在籍区分・部署略称を含む連続した青い領域とする。番号セルだけの別背景・二段間の白帯を残さず、左マーカーと選択状態の文字も維持する。行選択は現在表示中の12桁番号と所属条件を再確認して詳細を切り替える。
  • 6タブの選択状態は形・枠・背景・文字を併用し、Tab／Enterなどの操作対象と読み取り可能な選択状態を持たせる。タブ切替自体はデータを再読込せず、履歴で選んだ行のキーは区分別に保持する。冒頭の不要テキストボックスは対象を実ソースで特定してから撤去し、履歴選択の入力部品は誤って消さない。
