11. モック承認・I1～I12（2026-10-08）

承認対象は人給連携画面の構成と操作動線。モックの架空人数・金額・日付やデモ用操作は業務仕様に採用しない。I1～I3はモック承認を根拠とし、個別の選択肢回答があったとは記録しない。

決定 回答・確定根拠 反映内容 理由
I1 モック承認による確定 支給回の全職員を既定の出力対象とし、職員を絞り込める 承認された出力画面の対象選択
I2 モック承認による確定 A/Mは一括指定と明細ごとの変更を可能とする。判断は職員が行う 承認された更新区分操作と既存の職員判断方針
I3 モック承認による確定 人給連携の同一画面に「支給回の状況」「出力」「取込・照合」を配置 利用者の「いいですね。これでいいです」によるモック承認
I4 A Excel出力前に支給回・人数・明細数・A/M件数を確認して出力 利用者が出力前確認ありを選択
I5 個別指定 照合はExcelの元となる最新版のアプリ計算結果データと給与簿データ。計算版を選ばせない 利用者指定：アプリと人給のデータ同士を一致させる
I6 A 差分のみを初期表示とし、全件表示へ切り替え可能 利用者の表示選択
I7 A 出力後に計算結果が変わっても最新版と照合し、変更を画面で通知 利用者の選択とI5の最新版照合
I8 C・方式未確定 人給エラー行をアプリで分かるようにする要件は維持。結果取得方式は未入力 人給のエラー情報形式・取得方法が未確認
I9 B 再出力は差分に対応する明細行のみを初期選択し、職員が対象を変更可能 利用者の再出力対象選択
I10 B 人給への取込成功／一部失敗／失敗を手入力しない。給与簿取込後の照合で確認 利用者の操作選択。照合結果を人給取込処理の成功証明とは扱わない
I11 A 差分一覧は職員・対象期間・項目・アプリ値・給与簿値・差額を表示 利用者の差分表示項目選択
I12 B 給与班確定は確認ダイアログなしの確定ボタン操作 利用者の確定操作選択。全支給回の最新照合で差分ゼロが前提

画面要件は画面要件定義書、処理契約は詳細設計を参照。I8の方式、給与簿行と出力明細の対応キー、正式画面ID・物理名は未入力。D9以降の式確認は保留を維持する。
