# v1.21 給与詳細・認定簿軽量化

> 2026-09-24更新：下記v1.20要件は公開済み現行版の回帰根拠として保持する。今後の軽量化実装では「v1.21置換要件」を優先する。

## v1.21置換要件

|ID|要件|受入条件|
|---|---|---|
|UI121-01|給与詳細を固定モーダルから基準給与簿の専用表示へ置換|旧163見出し＋163値ラベルの固定モーダルを正式画面ソースから除去し、SCR-005支給明細とは別機能として到達できる|
|UI121-02|163項目を縦方向へ表示|定義書の項目順、163項目の重複・欠落なし。項目名を縦に追える|
|UI121-03|表示月範囲と列の動的生成|利用者が表示開始月～表示終了月を選択。範囲内の登録済み給与レコードだけを横列へ生成し、固定12列を作らない。範囲変更に追随|
|UI121-04|値と同月複数レコードを区別|登録済みレコードの0・負数・空欄を区別。同月複数レコードは別列で全件を表示し、支給年月日・番号等で識別。黙って合算・先頭採用しない|
|UI121-05|未登録月と期間の扱い|未登録月は列を表示しない。対象範囲内0件は空状態。開始月＞終了月は適用せずエラー表示。採用前・退職後だけを理由に列を除外しない|
|UI121-06|仮想化と到達性|163×月数のセルを静的作成せず、最終項目・最終月へ到達可能。見出しと値の対応、キーボード、200％表示を確認|
|UI121-07|通勤認定簿をHTMLへ一本化|通勤レコード選択後に正式HTMLを別タブ表示。旧Canvas認定簿、PDFViewer、PDF生成・保存、旧PoCをアプリから削除し、検証記録はGitHubに保持|

## v1.20現行版の回帰要件

対象は既存の自動開発_職員マスタ検索。2026-09-17の画像①〜⑤と6点の修正指示を根拠とする。旧STATUSの「主要15項目を維持」は今回の給与詳細要件に限り置き換える。メイン画面の概要15項目は維持。

|ID|要件|受入条件|
|---|---|---|
|UI120-01|給与詳細表示中の背景を薄くする|全画面半透明の背景と白いパネル。背景操作を抑止|
|UI120-02|給与詳細は163項目すべてを表示|定義書の項目順、163項目の重複・欠落なし。Dataverse値、0・負数・空欄を区別。横スクロールで末尾まで到達。縦方向で行を見切らせない|
|UI120-03|画像③の文言を削除|注意文が表示されず、空き領域が残らない|
|UI120-04|画像④⑤の部品を削除|100%に戻す、帳票に戻る、定型説明文を削除|
|UI120-05|認定簿の倍率・PDFを閉じるの横へ移動|同じヘッダー内で並ぶ。狭い幅では3操作が同じ第2行に並び、互いに重ならない|
|UI120-06|PDFを取得可能にする|アプリのPDF出力ボタン→職員情報入りPDFを別タブ表示→ブラウザのダウンロードボタン→ファイル保存、の操作を許容する。保存先はブラウザ設定による選択または既定フォルダでよい。保存ファイルはA4横2ページ、表示職員と認定IDが一致すること。プレビュー表示だけは不合格|

2026-09-17追加合意：利用者が上記4段階の操作を承認。人事院の空欄PDFは疎通確認用であり、受入対象は選択職員のデータを反映した認定簿。最新指示でOneDriveの使用・接続は禁止。Automateも使用しない条件で検討する。生成PDFの保存・URL取得は実機成功まで未完了とする。

同姓同名011/012、0件、複数月、0円、負数、再読込と検索回帰を実機で検査する。料金が発生する設定変更は実施しない。ユーザーは追加料金のない必要な権限追加、編集ロックのオーバーライド、テスト・公開を許可している。開始から60分を上限とし、超える前に処理状態を報告して中断する。

ソース候補・復元手順・PDFの検証上の注意は[最新の公開記録](../releases/2026-09-17-ui-pdf-comparison.md)を参照。既存の接続・データや対象外の帳票様式は保持する。
