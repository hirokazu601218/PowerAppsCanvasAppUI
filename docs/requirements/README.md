# 要件定義書：読み順と親子関係

このフォルダの対象は単一App ID `204a48dc-7f23-43dd-b934-4654a3cfa306`。要件の記載と、公開アプリでの実装・試験合格は別の状態として扱う。

| 文書 | 関係 | 説明・更新する場面 |
|---|---|---|
| [要件定義書](requirements.md) | 親 | 目的、適用範囲、現行機能要件R15～R23の入口。機能の変更要求が確定したら更新 |
| [業務要件（To-Be）](business-requirements.md) | 親の補助資料 | E・F・Gなどを章で管理。業務単位で更新し、現行実装とは区別 |
| [画面要件定義書](screen-requirements.md) | 親の子 | SCR-001～006の画面、遷移、権限、SCR-002/005の受入条件。画面固有の条件を変更するとき更新 |
| [非機能要件](non-functional-requirements.md) | 画面要件と兄弟 | 可読性、性能、信頼性等の判定条件。数値や適用環境の未決部分は未決一覧で管理 |
| [要件対応表](traceability-matrix.md) | 上記3冊に対する索引 | 要件→基本設計→詳細設計→試験、および機能・画面・共通・非機能の横方向の関係。仕様本文を重複して定義しない |
| [未決・未実装・未照合一覧](open-decisions.md) | 状態管理の兄弟 | 業務判断、確認された実装差分、保存先や権限の未照合。確定・修正・実測したときに元のIDへ反映 |

読む順は親の要件定義書→対象画面／非機能→対応表→未決一覧→[基本設計](../design/basic/README.md)→[詳細設計](../design/detailed/README.md)。
旧版の受入条件や今回統合した横方向の関係表の原本は[記録](../../records/docs/requirements/)にある。関係表の正本は現在の[要件対応表](traceability-matrix.md#横方向の関係旧要件間マトリクスを統合)。
