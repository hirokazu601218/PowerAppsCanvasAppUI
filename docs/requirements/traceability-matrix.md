# 要件・基本設計・詳細設計・試験対応表 v1.2（2026-09-27）

## 目的と判定方法

デジタル庁ガイド第７章の要件と設計の突合（参考7-5、RTM）の観点で整理する。

本表は要件から設計・試験への縦方向の対応。本書の横方向の関係表で依存・別機能を、[未決事項一覧](open-decisions.md)で業務判断待ちを確認する。

[要件定義書 v1.10](requirements.md)、[画面要件定義書 v1.1](screen-requirements.md)の現行要件IDを起点に、[基本設計書 v1.11](../design/basic/basic-design.md)、[詳細設計書 v1.10](../design/detailed/detailed-design.md)、[テスト実施要領](../testing/test-specification.md)の対応を示す。対象は[単一アプリ運用](../operations/single-app-workflow.md)のApp ID `204a48dc-7f23-43dd-b934-4654a3cfa306`。既存の要件IDは改番せず、同一内容のR番号と画面要件IDを両方追跡する。設計への記載、試験ケースの定義、実行可能なコード、公開Playerでの実測はそれぞれ異なる状態である。設計文書に記載がないことだけでアプリの未実装を断定しない。

以前のR・SCRの74行、追加済みの4行に加え、画面要件1～5章の既存の画面一覧・遷移・引継ぎ・権限制御に8つの追跡IDを付け、計86行を追う。**新しい業務要件を8件承認したという意味ではない。** 8つのIDは既存記述をグループ化したもので、5本の往路・5本の復路や全権限条件を1ケースで合格と判定しない。`NFR-*`は[非機能要件の検討ID](non-functional-requirements.md)であり、承認済みIDや実行済みの試験へ算入しない。

- `B全`＝[基本設計「現行アプリの全体構成」](../design/basic/basic-design.md#現行アプリの全体構成)、`B構`＝[「軽量化後の構成」](../design/basic/basic-design.md#軽量化後の構成)、`B配`＝[「軽量化後の配置」](../design/basic/basic-design.md#軽量化後の配置)、`B側`＝[「職員検索サイドバー」](../design/basic/basic-design.md#職員検索サイドバー)、`B機`＝[「現行画面の機能・状態・データ境界」](../design/basic/basic-design.md#現行画面の機能状態データ境界)。旧版の「構成」「配置」は現行設計の根拠にしない。
- `D10.x`＝[詳細設計10章](../design/detailed/detailed-design.md#10-scr-002軽量化設計2026-09-24)、`D11.x`＝[SCR-005試算設計](../design/detailed/detailed-design.md#11-scr-005-支給明細の内蔵仮例試算設計)、`D12.x`＝[SCR-001と共通設計](../design/detailed/detailed-design.md#12-scr-001と全6画面の共通設計)。1～9章は旧版履歴。設計への対応は公開版の実装確認を意味しない。試験欄の`—`は現行ケース未設定を示す。

## 変更時の更新手順

1. 要件を追加・変更するときはIDと適用範囲を確定し、本表の該当行を作成・更新する。競合する旧記述と変更理由を明示する。未採番の要件は勝手にケースIDへ転記せず、要件文書でIDの付与を検討する。
2. 基本設計と詳細設計の対応節を記入する。未設計なら`—`や`一部`のまま残し、設計・テスト完了と判定しない。要件変更時は関連画面、テーブル、HTML認定簿への影響も確認する。
3. 独立した期待値を持つ単体・必要な結合ケースを選び、[改修ごとの選定記録](../testing/change-records/README.md)に対象部品と理由を記す。既存のケースで不足する場合のみコード・ケース仕様を追加／更新し、試験記録に公開版・コミット・実測と判定を残す。
4. 文書の対応表の更新だけで実行済み・PASS・業務受入とはしない。本表は現時点でActionsが読んで網羅率を判定する仕組みではない。変更の意味的な妥当性と未解消行はレビューで確認する。

今回の設計更新で、既存の画面要件1～5章に8つの追跡IDと設計対応を追加し、SCR-002通勤HTMLとSCR-005の**内蔵仮例**の端数規則を詳細化した。一方、SCR-002の勤務・保険・税の保存先と権限、SCR-005の本番計算・個別端数規則、SCR-003／004／006の画面内部、公開ソースの読戻し、現行テストコードと実測は残る。追加設計・試験コードの作成、公開アプリの操作は本表の更新だけでは実施されない。
