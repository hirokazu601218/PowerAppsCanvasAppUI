# 要件・基本設計・詳細設計・試験対応表（2026-09-26）

## 目的と判定方法

デジタル庁ガイド第７章の要件と設計の突合（参考7-5、RTM）の観点で整理する。

[要件定義書 v1.08](requirements.md)、[画面要件定義書 v0.9](screen-requirements.md)の現行要件IDを起点に、[基本設計書 v1.08](../design/basic-design.md)、[詳細設計書 v1.08](../design/detailed-design.md)、[テスト実施要領](../testing/test-specification.md)の対応を示す。対象は[単一アプリ運用](../operations/single-app-workflow.md)のApp ID `204a48dc-7f23-43dd-b934-4654a3cfa306`。既存の要件IDは改番せず、同一内容のR番号と画面要件IDを両方追跡する。設計への記載、試験ケースの定義、実行可能なコード、公開Playerでの実測はそれぞれ異なる状態である。設計文書に記載がないことだけでアプリの未実装を断定しない。

- `B構`＝[基本設計「軽量化後の構成」](../design/basic-design.md#軽量化後の構成)、`B配`＝[「軽量化後の配置」](../design/basic-design.md#軽量化後の配置)、`B側`＝[「職員検索サイドバー」](../design/basic-design.md#職員検索サイドバー)。旧版の「構成」「配置」は現行設計の根拠にしない。
- `D10.x`＝[詳細設計10章](../design/detailed-design.md#10-scr-002軽量化設計2026-09-24)の該当節。1～9章は旧版履歴。`一部`は当該要件を実装できる粒度まで設計が定義されていないこと、`—`は３文書に対応する設計・現行ケースが見当たらないことを示す。
- `計画 LT-*`＝[SCR-002軽量化の試験ケース仕様](../testing/test-specification.md#scr-002軽量化追加受入2026-09-24)。**現行App IDで実行するテストコードの存在やPASSを意味しない。** `コード UT-*`／`IT-*`＝[現行E2E](../../e2e/current-app/navigation.test.ts)に実装済みのケース。実行結果はコミットと公開版を照合して別途判定する。
- `実測`＝[2026-09-26の検索試験記録](../testing/current-app-search-observation.md)。`UT-SRCH-001`はFAIL、`IT-SRCH-DETAIL-001`はBLOCKEDで、どちらも現行の安定ゲートに入っていない。旧版の試験や別App IDのPASSを現行アプリの合格へ転記しない。

表の試験列は**関連する検査観点**であり、同じケースIDが複数行にあっても全条件を検証できるとは限らない。要件の一部しか確認しない場合は残件を明記した。単体・結合・総合の実施判断は[全体テスト計画](../testing/test-policy.md)と[改修ごとの選定記録](../testing/change-records/README.md)で行う。総合テストのシナリオと実施時期は未確定。

## 変更時の更新手順

1. 要件を追加・変更するときはIDと適用範囲を確定し、本表の該当行を作成・更新する。競合する旧記述と変更理由を明示する。未採番の要件は勝手にケースIDへ転記せず、要件文書でIDの付与を検討する。
2. 基本設計と詳細設計の対応節を記入する。未設計なら`—`や`一部`のまま残し、設計・テスト完了と判定しない。要件変更時は関連画面、テーブル、HTML認定簿への影響も確認する。
3. 独立した期待値を持つ単体・必要な結合ケースを選び、[改修ごとの選定記録](../testing/change-records/README.md)に対象部品と理由を記す。既存のケースで不足する場合のみコード・ケース仕様を追加／更新し、試験記録に公開版・コミット・実測と判定を残す。
4. 文書の対応表の更新だけで実行済み・PASS・業務受入とはしない。本表は現時点でActionsが読んで網羅率を判定する仕組みではない。変更の意味的な妥当性と未解消行はレビューで確認する。

現時点で優先して埋める差分は、SCR-002の9月25日追加要件（編集・保存・破棄確認、選択行、給与簿の操作）、SCR-005の基本・詳細設計と現行ケース、全６画面の共通余白・遷移・権限の採番と試験である。追加設計・試験コードの作成、公開アプリの操作は本表の作成だけでは実施されない。
