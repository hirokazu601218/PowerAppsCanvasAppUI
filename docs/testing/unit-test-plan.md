# 単体テスト計画（現行アプリ）

[全体テスト計画](test-policy.md)の単体工程を、改修ごとに実施するための計画。対象は現行App ID `204a48dc-7f23-43dd-b934-4654a3cfa306` と `_STUDIO` 隔離データ。

## 対象と開始条件

改修した各画面部品・Power Fx数式・関連する処理を必ず対象とし、[試験選定記録](change-records/README.md)に部品と単体ケースIDを対応付ける。開始前に改修内容、入力値、独立した期待値、テストデータ、公開Playerの対象版を確定する。GitHub候補ソースと公開版の対応が未確認なら、公開Playerの現状試験として区別し、当該改修の単体テスト完了とは判定しない。

## 操作・判定

部品を実画面で操作し、入力、分岐、結果、エラー時の表示を対象仕様と照合する。画面から直接操作できない数式は、結果に到達する最小限の画面操作を選ぶ。既存の自動ケースで不足する分岐や期待値があれば追加・更新する。静的検査やPower Fxのエラー確認を併用できるが、実画面の観測の代わりにはしない。

| 現行の実装済みケース | 操作と独立期待値 | 実装 |
|---|---|---|
| `UT-HOME-001` | ホームの職員マスタ検索ボタンを操作し、03会計課の架空職員7名の一覧へ遷移する | [navigation.test.ts](../../e2e/current-app/navigation.test.ts) |

実装済みケースはホーム遷移の範囲だけを確認する。検索の `UT-SRCH-001` は[不一致の実施記録](../../records/docs/testing/current-app-search-observation.md)を踏まえた次回改修の設計対象であり、現行ゲートには未実装。別の改修部品へホームのケースIDを流用して合格としない。実施日時、コミット、App ID、公開版、操作と実測、判定、残件は[実施記録の様式](templates/test-execution-record.md)で記録する。改修部品のケースが失敗、未実施、または公開版の対応未確認なら単体工程を完了としない。
