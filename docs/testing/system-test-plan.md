# 総合テスト計画（策定待ち）

仕様・シナリオ・実施時期の判断待ちは[未決事項一覧 D-07](../requirements/open-decisions.md)にまとめる。公開後の読戻し・単体／結合ケース再実行は[現行アプリの変更要求から公開・文書反映まで](../operations/current-app-request-to-release.md)で扱う。

[全体テスト計画](test-policy.md)における総合工程。対象は現行の単一App ID `204a48dc-7f23-43dd-b934-4654a3cfa306` と隔離データ。複数機能を通す業務シナリオ、開始・終了条件、非機能観点、実施時期はユーザーと後続で策定する。

シナリオ確定後に、業務フロー、対象機能、データ、操作順、独立期待値、実施環境、担当、判定方法を本書へ追加する。その上で自動化する範囲を決める。現在の単体・結合E2Eを毎回実行しても、総合テストの実施またはPASSと扱わない。

改修ごとの[試験選定記録](change-records/README.md)では、総合テストは `deferred` と理由を記す。業務の受入判断は[受入テスト計画](../acceptance/user-acceptance.md)に分ける。

## v25の総合テスト候補（D-07判断待ち）

下表は実施仕様の候補であり、実施済みのケースではない。現行の[公開後6ケース](../verification/postpublish/change-20260928-scr002-history.json)は各表の表示と職員切替を中心に検証しており、複数機能を通す業務シナリオの合否には転用しない。

| 候補 | 操作の範囲 | 確定前に決める独立期待値・前提 |
|---|---|---|
| 採用・異動後の確認 | 隔離職員を検索し、基本情報→勤務条件→社会保険→税固定控除と住民税履歴→給与簿を確認 | 対象者、時点ごとの期待値、履歴の件数と適用期間、欠損値の扱い、給与簿との照合元。編集・保存を含めるかもD-02で決める |
| 退職・別職員への切替 | 退職済みの隔離職員を選び、履歴と通勤を確認後、別職員へ切り替えてSCR-005との往復を行う | 退職前後の対象期間、表示／非表示条件、旧値の消去、画面をまたぐ選択状態と独立した試算期待値 |
| 所属をまたぐ拒否 | 実効所属の異なるテスト利用者で検索・直指定・履歴表示・帳票起動を試みる | D-01で権威ある所属取得元と拒否条件を決め、実効権限の異なるアカウントと架空職員を用意する。画面の確認用所属選択だけで代用しない |

実施前にD-07で対象シナリオ、開始・終了条件、テストデータの独立期待値、実施時期・担当、非機能項目と自動化範囲を確定する。正式テーブルの個人情報を試験目的で投入しない。
