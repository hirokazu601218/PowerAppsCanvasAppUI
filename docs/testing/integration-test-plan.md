# 結合テスト計画（現行アプリ）

[全体テスト計画](test-policy.md)の結合工程を、改修の影響に応じて実施するための計画。対象App IDと隔離データは[単体テスト計画](unit-test-plan.md)と同じ。

## 対象と開始条件

改修部品から他部品、複数部品、画面、データ、帳票、外部接続に影響が及ぶ場合に実施する。影響がない判断も[試験選定記録](change-records/README.md)に根拠を残す。関連する単体ケースの結果を先に確認し、入力・受渡し・期待値と公開版の対応を特定する。

## 操作・判定

画面操作を通じて部品間の値の受渡し、状態の同期、検索と詳細の整合、異常時の影響を照合する。選定した結合ケースの不足を確認し、必要なケースを追加・更新する。改修部品だけの表示を再確認して結合の合格に代えない。

| 現行の実装済みケース | 操作と独立期待値 | 実装 |
|---|---|---|
| `IT-SRCH-DETAIL-001` | 会計課の検索結果で架空職員011を選択し、詳細の職員番号と所属に011／03会計課が渡る | [search.test.ts](../../e2e/current-app/search.test.ts) |

このケースは検索結果と詳細の連携だけに適用する。他の連携改修は別ケースを選ぶ。[実施記録](templates/test-execution-record.md)へケースごとの操作、実測、PASS/FAIL/BLOCKED/NOT_RUNと残件を記録する。関連する単体ケースと必要な結合ケースの完了、公開版の照合を終了条件とする。
