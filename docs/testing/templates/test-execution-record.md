> 選定の根拠は同じ変更IDの[試験選定記録](../change-records/README.md)を参照。PR作成時は判定を `NOT_RUN` とし、Actions実行後に観測結果を記入する。

| 項目 | 記入内容 |
|---|---|
| 変更ID／PR | 未記入 |
| 実施日時・タイムゾーン／確認者 | 未実施 |
| GitコミットSHA／Actions run URL | 未実施 |
| 対象環境／App ID | `68e00049-b7e5-eda6-9888-9a3cc493c5be` ／ `204a48dc-7f23-43dd-b934-4654a3cfa306` |
| 公開版の表示・読戻し／Git候補との対応 | 未確認。公開Playerの現状試験と区別する |
| 試験データ・前提 | `_STUDIO`隔離データ、テスト利用者の表示範囲を記入 |

| 工程・ケースID | 改修部品／影響先 | 入力・操作と期待値 | 実際の画面結果と証跡（ログ・run URLなど） | 判定 | 残件・再試験 |
|---|---|---|---|---|---|
| 単体・UT-... | 未記入 | 未記入 | 未実施 | NOT_RUN | 未記入 |
| 結合・IT-...（必要な場合） | 未記入 | 未記入 | 未実施 | NOT_RUN | 未記入 |

判定は `PASS`（期待値と一致）、`FAIL`（不一致）、`BLOCKED`（認証・環境等で判定不能）、`NOT_RUN`（未実施）。実行しない結合テストは行を消し、選定記録の「不要」とした理由を参照する。総合テストの業務シナリオ・時期は未確定の間、独立したPASSを付けない。業務受入は[受入テスト計画](../user-acceptance.md)に記録する。

Actionsのstep summaryとジョブの成功・失敗は自動実行の一次記録。上表は、期待値と画面の実測、公開版の対応、残件を人が確認して残すために使う。成功したジョブでも未照合の公開版を「Git候補のPASS」にしない。資格情報、認証状態、実在の職員情報をGitHubへ転記しない。
