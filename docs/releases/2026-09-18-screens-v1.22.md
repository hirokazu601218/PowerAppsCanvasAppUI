# UI試作 v1.22 公開記録（2026-09-18）

Issue #52。画面要件定義書 v0.6 を元に、既存の自動開発アプリへ5画面を追加し、既存職員検索と合わせて6画面にした。依頼時に認められたダミーPower Fx・内蔵テスト値を使用するUI検討用公開であり、業務計算完成版ではない。

## 実装

| 要件 | 実装 |
|---|---|
| SCR-001 | ホーム、サインイン中アカウント、5つの画面リンク、確認用所属・権限切替 |
| SCR-002 | 既存職員検索を維持し、ホーム・支給明細への遷移と対象月を追加。所属で検索元を制限 |
| SCR-003 | 月次の日別勤務一覧、部分欠勤時間の仮入力、月次登録 |
| SCR-004 | 期末・勤勉手当の支給率入力と仮登録 |
| SCR-005 | 固定した対象職員・月と上部計算サマリー、縦スクロールの支給／控除内訳、個別折畳み、再計算、未登録・0円の区別 |
| SCR-006 | 管理者向け仮入力初期化。一般利用者のホームボタンは無効 |

新規操作ボタンはModernButton。ドロップダウン・数値入力・文字ラベルは、既存アプリで動作する部品との互換性を優先してClassic/DropDown、Classic/TextInput、Labelを使用した。

9月は給与支給総額200,000円、控除48,200円、現金支給151,800円。10月は未登録、11月は登録済み0円。職員番号を選択キーとし、同姓同名を区別する。所属変更時に選択を破棄し、管理者でも選択所属に限定する。

## UI試作としての範囲・残件

- 確認用の所属・管理者切替はダミー。実ユーザーと所属／ロールの対応、サーバー側のアクセス制御を新設したものではない。
- 新しい勤務・支給率・控除は仮値で、仮入力はセッション内のみ。職員・月ごとの永続保存、正式給与計算、確定データ契約の全ケースは後続。勤務日カレンダーも固定の説明用データ。
- 新画面の職員候補は既存Dataverseの架空職員データを読み、日額・欠勤時間単価などを画面検討用に上書きする。既存画面の給与履歴と新画面の仮計算は同じ計算モデルではない。
- Dataverseの書込み、テーブル変更、権限追加、課金変更なし。欠勤時間単価の実テーブル追加 [Issue #51](https://github.com/hirokazu601218/PowerAppsCanvasAppUI/issues/51) は未完了のまま維持。
- 標準SMK-01の新規コンテキスト3回、8条件レイアウト、全P0、キーボード／アクセシビリティ、PDF回帰は未実施。標準自動受入完了版への昇格・成功タグは行っていない。今回確認したデスクトップUI以外は追加検証が必要。
- 既存のPDF直接保存の課題は継続。旧自動配布パッケージは更新しておらず、旧bridgeによる再配布に使わない。
