## 対象

|役割|表示名|固定App ID|
|---|---|---|
|唯一の継続開発・公開アプリ|自動開発_職員マスタ検索（旧 `自動開発_職員マスタ検索_STUDIO_EDIT`）|`204a48dc-7f23-43dd-b934-4654a3cfa306`|

環境は `StaffMaster-Automation-Test`（`68e00049-b7e5-eda6-9888-9a3cc493c5be`）。このアプリは現時点で `M_職員基本_STUDIO`、`T_通勤_STUDIO`、`T_基準給与簿_STUDIO` と隔離版HTMLを参照する。表示名だけを変更したので、接続先、App ID、共有、公開版、画面機能は変更していない。検証データを本番データとして扱わない。元テーブルの作成・更新・削除を暗黙に許可しない。

次の4アプリは当面保管するが、新規機能の編集、通常公開、配布先として使わない：`削除候補_自動開発_職員マスタ検索`（旧安定版、ID `362ac991-eead-4f07-8373-afdb3ebfdba1`）、`削除候補_DEPLOYPROBE_AUTOPUBLISH_20260924`（ID `c5dece33-b799-43be-a55b-3344c83979d9`）、`削除候補_DEPLOYPROBE20260924`（ID `bd256de5-c7a5-4487-9aef-91ee26d4c946`）、`削除候補_検証専用_職員マスタ_20260918_残件`。接頭辞は削除許可を意味しない。削除は利用状況・依存・復旧手段を別途確認し、ユーザーが判断する。

## 改修・確認・公開

改修の試験選定は[全体テスト計画](../testing/test-policy.md)、[改修ごとの選定記録](../testing/change-records/README.md)、[現行アプリE2E](../testing/current-app-e2e.md)を参照する。公開Playerの試験結果とGitHub候補ソースの同一性を別に確認する。

修正・機能追加の指示を変更要求として記録し、実行指示後に構築・試験・公開・公開版照合・文書反映を一つの作業として扱う場合は[現行の変更要求から公開・文書反映まで](current-app-request-to-release.md)を適用する。旧App ID向け配布Actionsを現行IDへ無検証で流用しない。

1. **Codex**は唯一の対象App IDを照合し、GitHubの変更候補を実装する。既存の隔離テーブルとテストレコードで対象機能を検証し、Studioの数式エラーと意図しない書込みがないことを確認する。
2. **Codex**は保存版と公開版を区別して記録し、対象のアプリ1件へ公開する。公開Playerの変更内容、検索・詳細・帳票など影響範囲、専用ユーザーの必要な回帰を確認し、失敗したら元内容の復旧とPlayerを確認する。公開すると共有先に変更が見えるため、事前に対象と影響を把握する。
3. **Codex**は公開版と変更要求・候補ソースを照合し、要件定義書・基本設計書・詳細設計書と影響する結合ケース仕様を更新する。公開後の[照合Actions](../../.github/workflows/current-app-postpublish-docs.yml)で版・読戻し・選定ケース・文書差分を確認する。
4. **ユーザー**は同じアプリの公開Playerで画面・業務動作を確認し、修正指示または受入判断を伝える。修正指示ならCodexが同じアプリで修正・再試験し、文書も再照合する。別アプリへの移送工程は設けない。
5. **Codex**は候補ソース、公開結果、確認した機能、未検証事項を同じWorkとGitHubへ記録する。実機・200%・業務受入など未実施の項目を合格とは扱わない。

Power Appsの保存は公開を意味しない。同じApp IDの版履歴と公開Playerを使い、意図しない版を公開した場合は対象版を特定して復旧し、読戻しとPlayerを再確認する。テストで実証済みの「非管理Solution importで即Live」の経路を単一アプリに自動適用しない。

## 旧自動化との境界

`records/config/apps/staff-master.json`、旧Actions／E2Eの一部とPR #73の配布候補は旧App ID `362ac991-eead-4f07-8373-afdb3ebfdba1` を指している。**表示名を変えても対象IDは変わらない。** 旧App ID向けのpack/import/publish/restore/配布資格認定を現在のアプリの手順として起動しない。ID、接続、テスト、バックアップと復旧先を新App ID向けに修正し、実際の公開Player・読戻しまで検証するまでは、自動配布成立とは記録しない。旧自動化の結果は履歴であり、対象変更だけで合格とみなさない。

将来本番データを利用する場合は、隔離テーブルと隔離帳票の切替、CRUD権限、共有、利用者受入を別の変更として審査・検証する。本方針の採用だけでは本番データへの切替や業務本番利用可を宣言しない。
