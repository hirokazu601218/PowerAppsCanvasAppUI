# ChatGPT Sol Work 運用方針 v1.01

## 1. 方針

本プロジェクトの要件定義、基本設計、詳細設計、Power Apps Source Code形式YAML／Power Fxの開発、静的テスト、レビュー、GitHub反映をChatGPT SolのWorkで行う。Codex Desktop／Webを前提としない。

GitHubのmainを共有正本とし、チャット履歴だけを仕様根拠にしない。着手時はREADME、STATUS、要件、基本設計、詳細設計、デザイン基準、受入基準を確認する。

## 2. 役割

| 担当 | 役割 |
|---|---|
| ChatGPT Sol Work | 要件整理、設計、実装、静的検査、自己レビュー、文書・GitHub更新 |
| ユーザー | 業務判断、変更承認、Power Apps Studioでの貼付・操作・目視確認、リリース承認 |
| GitHub | 正本、版管理、差分確認、復元 |

## 3. 実装ルール

- UI成果物はPower AppsのSource Code形式YAMLとPower Fxとする。HTML／Reactによる代替アプリは作らない。
- 利用可能な部品はモダンコントロールを優先し、機能・互換性上の例外を記録する。
- 通常利用者には `.paste.yaml` を案内し、管理用 `.pa.yaml` の画面Childrenと一致させる。
- Classic/Button@2.2.0へ未対応の `AccessibleLabel` を追加しない。
- PDFViewerをGroupContainerの子にしない。対象環境のコントロール版を確認する。
- 初期表示をOnVisible／OnStart／タイマーだけに依存させず、検索0件時に旧職員の詳細や帳票を残さない。
- 実データ、資格情報、環境固有URLをGitHubへ追加しない。試作データは架空とする。
- 画面ソースの版は0.01刻みとし、新版の確認後に旧版をGit履歴へ集約する。
- v1.11をB案＋職員検索サイドバー開閉の完全版として作成する。v1.12以降は変更コントロール単位の差分配布を原則とする。
- 差分は[コントロール単位差分配布方針](control-diff-policy.md)に従う。コントロール名や変数名を版が変わるたびに一括変更しない。
- GitHubの完全版正本は必要な箇所だけを編集して維持する。全文のLLM再生成や毎回のチャットへの全文掲載を作業要件にしない。

## 4. 作業手順

1. Workで変更要求を要件IDと受入条件へ反映する。
2. 影響する基本・詳細設計、デザイン基準、テスト項目を更新する。
3. WorkでYAML／Power Fxを作成または修正する。
4. 構文・参照・項目数・既知エラーを静的検査する。
5. Workで要件ID単位の自己レビューを行う。
6. ユーザーがPower Apps Studioで貼付、操作、見た目を確認する。
7. 結果と未実施事項を記録する。ユーザーの格納指示に基づく試作候補は「Studio未検証」と明示してGitHubへ反映できる。本番利用可への昇格はユーザーの実機確認・承認後とする。

## 5. 検証と記録

ローカル検査はMicrosoft公式コンパイラやPower Apps Studioの実行試験ではない。実機確認を行っていない項目を合格と記載しない。検索、ページ移動、対象職員切替、0件、帳票、PDF、画面サイズ、キーボード操作の結果を分けて記録する。

スクリーンショットだけで検索やPDF生成を合格にせず、期待値、実結果、環境、対象版、残件を残す。仕様と実装が矛盾した場合は作業を止め、STATUSへ記録してユーザーへ確認する。
